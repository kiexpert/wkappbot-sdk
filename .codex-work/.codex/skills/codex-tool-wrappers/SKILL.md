# Codex Tool Wrappers

## Steps

1. ARCHITECTURE: Codex native write_file/read_file blocked via hook exit 2. Codex must use shell to call cmd wrappers that match Claude built-in tool names.
2. WRAPPER SET: Edit.cmd Write.cmd Read.cmd Glob.cmd Grep.cmd.
3. SOURCE: personal-docs/tools/ owns .cmd and .ps1 source files. WKAppBot/bin/ holds symlinks installed by wkwrap --install.
4. INSTALL: wkwrap --install extended to mklink WKAppBot/bin/Edit.cmd -> personal-docs/tools/Edit.cmd. Symlinks not copies, no wk prefix.
5. INTERFACE: Each wrapper reads stdin JSON matching Claude tool_input format. Edit: {tool_name:'Edit',tool_input:{file_path,old_string,new_string}}. Write: {tool_name:'Write',tool_input:{file_path,content}}.
6. HARNESS INTEGRATION: wrapper pipes stdin JSON to wkharness.ps1 unchanged. wkharness sees tool_name:'Edit' same as real Claude Code Edit call. Zero harness changes needed.
7. EDIT.CMD IMPL: thin relay to Edit.ps1. Steps: (1) read stdin JSON (2) pipe to wkharness.ps1 exit 1 if blocked (3) parse file_path old_string new_string (4) .bak backup (5) UTF-8 read replace UTF-8 write.
8. WRITE.CMD IMPL: relay to Write.ps1. Steps: wkharness pre-check, .bak backup, UTF-8 full overwrite.
9. CODEX CONFIG: ~/.codex/config.toml PreToolUse hook matcher=write_file exits 2 with 'use Write.cmd via shell'. matcher=read_file exits 2 with 'use Read.cmd via shell'.
10. AGENTS.MD RULES: FORBIDDEN write_file read_file. REQUIRED shell echo json pipe to Write.cmd or Edit.cmd. Never use native Codex file tools.

Agent.cmd / Agent.ps1 calling convention (2026-05-27, CONFIRMED): the args path goes bash -> cmd.exe %* -> powershell, which corrupts non-ASCII via the OEM codepage, mangles cmd metachars (& | < > ^), and CANNOT carry newlines. Hardening applied: Agent.cmd now runs chcp 65001 right after @echo off, and Agent.ps1 sets Console In/OutputEncoding to UTF-8 no-BOM after ErrorActionPreference. STANDARD CONVENTION: for any MULTILINE or special-char prompt, pipe it via stdin using a bash heredoc with a quoted delimiter (Agent.cmd --model haiku followed by a heredoc body); Agent.ps1 reads stdin verbatim as the prompt with no tokenization. Single-line ASCII prompts may remain a quoted positional arg. A native Agent.exe build would fix codepage+metachars on the args path but still cannot carry newlines, so stdin stays canonical for multiline. Verified end-to-end: Korean round-trip and a multi-paragraph investigation prompt both passed cleanly via stdin heredoc.
22. AGENT.CMD CLI-ARG VS STDIN-HEREDOC CONVENTION (2026-05-27, MANDATORY): Agent.cmd supports two calling patterns. (1) CLI args (simple ASCII): Agent.cmd 'prompt text' --model haiku (routed through cmd.exe, limits non-ASCII). (2) STDIN heredoc (RECOMMENDED for multiline/special-chars): Agent.cmd --model haiku << 'EOF' / prompt line 1 / prompt line 2 / EOF (piped via bash, preserves all characters). Use pattern 1 for single-line ASCII only. Always use heredoc for SPEC blocks, multiline tasks, or prompts containing shell metacharacters (&, |, <, >, ^, Korean text). See codex-opus-agent-delegation step 17 for full example.
