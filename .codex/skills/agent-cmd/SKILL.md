# Agent.cmd: universal delegation front door

## Steps

- `wkappbot skill read agent-cmd --if-newer   # re-read only if the cache changed`

1. WHAT: Agent.cmd is the ONE front door for every delegation. Pick the tier with the model flag. When the caller is Opus it runs in background by default, because foreground delegation is blocked so the user gets an immediate reply.
2. MODELS: model haiku, sonnet, opus route to Claude tiers; codex, codex-mini, gpt-mini route to codex; gemini, flash route to gemini; ask-gpt, ask-gemini, ask-triad, ask-groq, ask-cerebras route to the web intelligences (the wkappbot ask family). One flag, every brain.
3. EVIDENCE: the recursive-dialectic gate counts ONLY Agent.cmd cheap dispatches, one clean pattern, no messy raw-command scan. Delegate cheap work through Agent.cmd to build the evidence that unlocks Sonnet and Opus. See harness-token-waste-tracker and the cheap-evidence pool.
4. BRIEF: every brief needs 3 wkappbot skill read refs (agent-brief-guard). A multiline or non-ASCII brief MUST use a bash heredoc with a quoted delimiter, or the file flag with a utf8 path, because the plain args path mangles newlines and the OEM codepage.
5. NAV: command recipes and dispatcher syntax go to agent-cmd-howto. Routing-table internals, alias build status, and history go to agent-cmd-ref. Tier routing policy is claude-code-agent-tier-routing.

The auto pool is capability-gated then pace-filtered (see wk-ai-tools-routing): a tool-requiring chore never routes to a tool-less model.
7. CONSUMER-CONTEXT MULTILINE SYNTAX FOR Agent.cmd (user 2026-06-12): the multiline form depends on WHO invokes it. (A) From a BASH or Claude-Code caller -- pipe a single-quoted heredoc: Agent.cmd --model X << QUOTE-EOF then the multiline prompt then EOF on its own line. (B) From a CODEX or PowerShell caller (codex runs in PowerShell) -- use a PowerShell HERE-STRING: Agent.cmd @" (newline) the multiline prompt (newline) "@  on its own line; prefer the literal single-quoted form @ single-quote ... single-quote @ to avoid PowerShell variable interpolation. RULE: when you WRITE guidance that tells CODEX to delegate via Agent.cmd, ALWAYS show the PowerShell here-string form, NEVER the bash heredoc -- a bash heredoc fails inside PowerShell. The dispatcher (Agent.cmd) is unchanged; only the multiline EXAMPLE must match the consumer shell. See: powershell-here-string-multiline, korean-argv-cp949-hell-with-wkappbot-from-bash.

10. EXECUTOR-SANDBOX MATCH (2026-06-13, hard lesson): gemini CLI agents are WORKSPACE-SANDBOXED to the CWD project (e.g. wkappbot-sdk) + their own tmp -- they CANNOT read a SIBLING repo (e.g. wkappbot-kih) or the claude temp dir; read_file errors 'Path not in workspace: resolves outside allowed workspace directories'. Claude (haiku) subagents have NO such sandbox and read anywhere. CONSEQUENCE: a gemini-pro dispatch told to patch files in wkappbot-kih (while CWD=wkappbot-sdk) produced NOTHING -- every read was refused; only the spawn line proved it ran. So MATCH the executor sandbox to the TARGET repo: cross-repo or sibling-repo work -> route to claude/haiku (or run the agent with CWD set to that repo), NOT gemini. Gemini is correct ONLY for work inside the current project. Also observed: the wkharness BeforeTool hook TIMES OUT 60-87s under gemini (cross-family hook perf issue, separate). VERIFY by checking the agent did real reads, not just that it 'ran'. Cross: cross-family-harness-integration.
