harness:learn -- soft-nudge loop for self-evolving skills

Pattern for making Claude skills evolve automatically. CLAUDE.md harness:learn directives trigger on tool completions, reminding Claude to promote patterns to skills. Rules live in the environment; the environment guides its own evolution.

user/developer

Steps

  1. CONCEPT: Rules live in CLAUDE.md harness section. When Claude edits CLAUDE.md (or matches any harness:learn pattern), wkharness-post.ps1 fires a reminder: promote this to a skill. Loop: observation -> CLAUDE.md edit -> harness:learn fires -> skill update -> skill read at next session start -> changed behavior. The system remembers even when Claude forgets.
  2. HOW TO ADD A TRIGGER: append to CLAUDE.md harness section -- '## harness:learn Edit.*CLAUDE\.md' -- fires when Claude edits CLAUDE.md via Edit tool. Pattern is tool_name:file_path regex. Examples: Edit.*CLAUDE\.md (rule added), Edit.*AGENTS\.md, Bash.*suggest.*resolve (resolve workflow), Edit.*\.cs (code change).
  3. IMPLEMENTATION: wkharness-post.ps1 SELF-HARNESS section parses harness:learn directives and matches j.tool_name:j.tool_input.file_path. On match: prints snippet + 'promote to skill' reminder to stderr. Claude sees this on next turn.
  4. PHILOSOPHY: AI has no persistent memory across sessions. Externalizing rules into CLAUDE.md + skills creates a feedback loop that outlives the session. harness:learn is the bridge: it converts ephemeral observations into durable skill steps. Three components: externalized memory (CLAUDE.md) + environment trigger (harness:learn) + skill accumulation (skill edit). Rules beget rules.
  5. EXTEND: add harness:learn for any pattern you want Claude to reflect on. The directives themselves live in CLAUDE.md -- Claude can add new harness:learn lines when discovering new patterns, making the trigger system self-extending.
  6. DISTINCTION from harness:done: harness:done watches tool_response OUTPUT (what was said/returned) -- useful for detecting symptoms like 'skipped' or error strings. harness:learn watches tool_name:file_path ACTION (what was done to what file) -- useful for detecting intent like 'edited a rule file'. done=reactive to content. learn=reactive to action. harness:done can also execute commands via ! prefix; harness:learn only prints a reminder. Use done for output-pattern guards, learn for action-based learning nudges.
