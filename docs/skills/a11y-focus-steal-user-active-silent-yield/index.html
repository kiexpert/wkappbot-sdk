a11y focus-steal: user-active silent yield in RestoreFocusWithRetryAsync

When RestoreFocusWithRetryAsync is fighting a focus steal (Chrome/Electron) but user is actively typing (<1.5s idle), treat it as an intentional user switch and bail out silently -- no more ForceForegroundWindow loop, no AutoBugReport noise.

user
a11yfocus-stealuser-activesentinelbailoutfocusless-first

Steps

  1. Sentinel retries ForceForegroundWindow up to 5s (150ms * 33 attempts)
  2. Inside loop: check NativeMethods.GetUserIdleMs()
  3. If <1500ms (user is typing/clicking) set userBailed=true and break
  4. On userBailed return false immediately -- no IME restore no cursor restore no bug report
  5. The user's foreground choice wins; only file reports for true involuntary steals
  6. Usage context: wkappbot a11y invoke / a11y find / a11y inspect / a11y windows / a11y hack paths all go through this sentinel; user-active yield prevents spam during intentional focus switches
  7. Also covers ask gpt / ask claude / ask gemini / ask triad / ask-* CDP flows: prior sessions saw UIA focus steal (hwnd attach, SetForegroundWindow) during ChromeLauncher->CDP attach -- same sentinel bailout applies
