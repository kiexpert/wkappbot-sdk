Payment to License Activation Flow - KIS transfer + GitHub collaborator auto-grant

End-to-end flow from KRW bank transfer to active license: KIS incoming transfer detection, GitHub ID parsing from memo, collaborator add, pending invite UX, acceptance, expiry, renewal.

Steps

  1. Pricing: 100,000 KRW = CDP tier (read permission), 500,000 KRW = Sudo tier (write permission); transfer to KIS account [YOUR_KIS_ACCOUNT].
  2. Memo (depositor name field) MUST be the payer's GitHub username verbatim; mismatched memo blocks auto-grant.
  3. Detector: scripts/kis_payment_watcher.py polls KIS hourly, parses memo field, extracts github_id and amount, derives tier (100k=read, 500k=write).
  4. Grant: detector calls 'gh api repos/***/wkappbot-sdk/collaborators/{github_id} -X PUT -f permission=read' (or write); tx_key recorded with expiry date in commit message.
  5. Pending invite UX: wkappbot startup detects pending invite via GitHub API; shows blue toast bottom-right with 'GitHub notification check' button (auto-dismiss 15s, non-blocking); CDP/Sudo features stay locked, Free features keep working.
  6. Acceptance: user clicks GitHub notifications -> View invitation -> Accept; on next wkappbot startup license check returns tier and gated features unlock; toast clears.
  7. Expiry: tracked in .github/licenses/{user} commit message (tier=cdp+sudo cdp=<ISO8601> sudo=<ISO8601>). Duration = floor(amount_usd * 30 / 100) days: USD100=30d, USD200=60d, USD363=108d. C# enforces expiry: sudoActive requires perm=write/admin + tierStr contains sudo + sudoExpiry > now(). Revocation: remove collaborator OR let expiry date pass.
  8. Renewal: pay again with same memo; new tx_key issued, permission re-granted, commit message updated with new expiry date.
  9. Tier upgrade (CDP -> Sudo): pay 500k with same memo; detector overwrites permission=read with permission=write, updates commit expiry.
  10. Verification: 'wkappbot license status' shows User/Tier/CDP/Sudo with expiry countdown. Command is Launcher-owned fast-exit -- never reaches Core.
  11. License check architecture (LicenseStatus.cs): 2 API calls. Call 1: POST api.github.com/graphql -- {viewer{login} repository{viewerPermission}} -- returns login + perm in one shot, tamper-proof. Call 2: GET /repos/.../commits?path=.github/licenses/{user} -- parse tier=, cdp=, sudo= from trusted commit message (author must be in TrustedAuthors set).
  12. Token auth: (1) GH_TOKEN/GITHUB_TOKEN env var, (2) hosts.yml oauth_token, (3) 'gh auth token' keyring fallback. If all fail, prints login guidance and exits 1.
  13. SUBSCRIBE.md KNOWN ISSUES (fixed 2026-05-01, verify on future edits): (1) Cancel section used to say 'at the 30-day mark' -- WRONG; expiry = floor(amount_usd*30/100) days, not always 30. Fixed to 'at your expiry date (check with wkappbot license status)'. (2) Pending invite section used to say 'click to accept' -- INACCURATE; actual toast shows GitHub notification check button + 15s auto-dismiss. Both fixed in SUBSCRIBE.md.
