grap hwnd volatility: hwnd stale between find and use

hwnd returned by a11y find becomes invalid if the window is destroyed/recreated between find and use. When this happens, the runtime falls through to title wildcard + --nth 1 fallback. Document the lifecycle and the correct usage pattern.

user/developer

Steps

  1. a11y find returns 'hwnd:0xXXXXXXXX' which is valid at query time. If the process recreates the window (common in WPF, Chrome, HTS), the hwnd is stale within seconds.
  2. Best practice: use hwnd: form only for immediate single-step operations. For multi-step sequences (find -> click -> type), re-query at each step or use title-based grap which re-resolves dynamically.
  3. Mitigation in runtime: IsWindow() check before each operation; if stale, falls back to title-wildcard + --nth 1. This fallback is visible in logs as [A11Y] hwnd stale -> retry with pattern. Consider using wkappbot a11y find directly before each step in automation scripts.
