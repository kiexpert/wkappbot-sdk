Suggest 2-of-2 Co-Resolve: Cross-Author Confirmation

When wkappbot suggest resolve is called by a different channel than the suggest author, requires 2-of-2 confirmation before marking resolved. Prevents maintainer fake bulk-resolves.

user/developer

Steps

  1. resolver_channel = AbbreviateCwd(CWD) compared case-insensitively to suggest.from
  2. Cross-author 1st resolve: writes half_resolved_by/note/at/skill + half_resolved_evidence (script content inline) + half_resolved_evidence_ext to suggest entry, posts Slack thread asking author to confirm.
  3. Cross-author second resolve (other party): completes 2/2, moves to history with both notes
  4. Same-author self-resolve (full flow): requires --confirm --skill X --commit <hash> --class <ClassName|skill-only>. Commit message MUST contain keywords from suggest title (guard checks word-by-word). If no fix commit exists, use git commit --allow-empty -m '...' with title keywords embedded. --class skill-only for doc/skill-only changes.
  5. --force reason: bypasses gate, posts override notice to Slack thread
  6. --confirm flag: 2nd-party confirmation path. Skips ALL evidence file checks (goto SkipEvidenceChecks). Only requires --skill. Moves to BOTH resolver history (wkappbot.hq/) AND suggester history ({suggest.cwd}/.wkappbot/).
  7. Verified 2026-04-26: test-suggest-resolve-coresolve.sh (resolve ts=2026-04-26T10:44:21.4731572Z)
  8. AUTO-CONFIRM (Eye-side, runs at startup + hourly): suggest auto-confirm [--dry-run]. Pre-check binary built after half_resolved_at → run stored evidence script in this context → pass: --confirm → history. fail: stays HALF.
  9. SUGGESTER CHECK (author-side, ID only): wkappbot suggest check <ts>. Shows: fixed-by + note + runs regression script → PASSED/FAILED. Offers 'suggest check <ts> --confirm' or add-requirement. No evidence flags needed for original author.
  10. DUAL HISTORY: on full resolve, appends to (1) {wkappbot.hq}/suggestions_history.jsonl (resolver/WKAppBot) AND (2) {suggest.cwd}/.wkappbot/suggestions_history.jsonl (suggester project). Each project owns its audit trail.
  11. SUGGESTER GUARD (2026-05-01): when suggester (same channel as suggest.from) runs resolve WITHOUT --confirm: (A) if 1/2 already exists → ERROR + copy-pasteable 'suggest check <ts> --confirm', return 1. (B) if no half yet → INFO reminder that resolve is maintainer's command + 'suggest check <ts>', proceeds anyway (same-author still allowed).
  12. REQUIREMENT DESIGN RULES (learned 2026-05-09): (1) Never hardcode hwnd — session-specific, always stale next run. (2) Never test transient state (popup visible, specific dialog open) — will fail when popup gone. (3) Test behavior that is reproducible any time. (4) If bug is 'cmd X fails', requirement should test 'workaround Y works' not 'X now succeeds' — X won't succeed until fix ships.
