Skill Authoring Rules + Contribute & Edit Workflow

T1 core tier. Decision rules for wkappbot skill contribute and edit: English-only rule, never-direct-edit-json safety, update-before-delegate order, Codex 64/1024 hard limits. Detail commands in skill-contribute-edit-howto; history/traps in skill-contribute-edit-ref.

Steps

  1. RULE: write ALL skill content (title, desc, steps, tags) in English only. Korean wastes 2 to 3 times the tokens and bloats context for every AI reading the skill.
  2. SAFETY: NEVER directly edit .skill.json with Edit, Write, or wkedit tools. Always go through wkappbot skill contribute or wkappbot skill edit so the catalog stays registered, encoding stays UTF-8, and install state updates.
  3. ORDER: update the skill BEFORE delegating. skill-update-pending guard fires when code changes without a matching skill update. Pattern: make code change, immediately wkappbot skill edit --add-step describing what changed and why, THEN spawn Agent or wkcodex. Reverse order causes repeated blocks and wastes tokens.
  4. CODEX HARD LIMITS: ID name must be 64 chars or fewer AND desc must be 1024 chars or fewer. Either violation = Codex silently skips the skill entirely (startup warning only, no error). T2 suffix -howto adds 6 chars; T3 suffix -ref adds 4 chars. Reserve a 6-char budget when planning a -howto sibling.
  5. NAVIGATION: command syntax and cross-repo flow live in skill-contribute-edit-howto. Shell traps, pipe-char workaround, verified-test history, maintainer sync live in skill-contribute-edit-ref. Consult those tiers when contribute fails or when you need a command beyond the four decision rules above.
