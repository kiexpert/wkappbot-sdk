a11y find FastExit + UIA skip for Electron/MFC (1-5s performance)

Key optimizations making a11y find/inspect/windows/ocr 1-5s instead of 50s in v6.2+. Electron/MFC UIA traversal skip, FastExit for read-only commands, MDI scan fast-path, cmd: fallback noise filter.

user/developer
a11yfindperformanceelectronmfcuiafastexit

Steps

  1. [ELECTRON-UIA-SKIP] VS Code and other Electron apps have window class Chrome_WidgetWin_1 but are NOT Chromium browsers. UIA traversal on Electron caused 30s DLL unload deadlock. Guard: IsElectronWindow = (class == Chrome_WidgetWin_1) AND NOT IsChromiumProcess. IsChromiumProcess matches chrome/edge/brave/etc. -- real browsers still get full UIA coverage. Batch UIA traversal skipped for Electron during discovery; explicit targeting still works.
  2. [MFC-UIA-SKIP] MFC/Afx windows (nkrunlite, Heroes4, HTS apps) have no meaningful UIA tree -- traversal wastes time with near-zero payoff. Discovery-phase UIA batch skipped. Automation still uses UIA when a single element is explicitly targeted. Detection by window class pattern (Afx*, MFC*).
  3. [FASTEXIT-PATH] Read-only a11y commands (find/inspect/windows/ocr/screenshot) use FastExit path: skips TeeWriter buffering and eye tick integration. Mutating commands (click/type/invoke) keep the normal path for audit/replay. FastExit cuts 1-2s off every discovery call.
  4. [MDI-SCAN-FAST-PROC-NAME] MDI child enumeration previously called ProcessGetById for each child HWND (slow WMI-ish lookup). Replaced with TryGetProcessNameFast using lightweight OpenProcess+QueryFullProcessImageName. On apps with 30+ MDI children the saving is substantial.
  5. [CMD-FALLBACK-NOISE-FILTER] FindByMultiField secondary cmdLine scan is skipped when top-level matches already found. IsSearcherProcess filter excludes bash/sh/cmd/powershell/pwsh/wkappbot* from cmd: matching -- these processes routinely have the search substring in their cmdlines. Prevents generic wildcard patterns from returning shells or wkappbot itself as false positives (e.g. VS Code matching a search term via its bash terminal child cmdline).
