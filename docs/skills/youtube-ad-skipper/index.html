YouTube Ad Auto-Skipper

Auto-skip/close YouTube ads in a loop via CDP a11y. Detects skip button, overlay close, and ad-showing DOM class. Reloads on unskippable ads.

Steps

  1. Run: powershell -File test/youtube-ad-skipper.ps1 [-Url <yt-url>] [-RunMinutes <N>] [-PollSeconds <N>] ROOT CAUSE for JS-click failure: YouTube checks event.isTrusted on the skip button; element.click() and CDP-dispatched mouse events both fail. Only OS-level UIA InvokePattern is treated as trusted. Use wkappbot a11y invoke (which calls IUIAutomationInvokePattern.Invoke under the hood). Skip button UIA grap: {proc:'chrome',cdp:PORT,domain:'www.youtube.com'}#*skip-button* (matches AutomationId 'skip-button:<N>'; do NOT use '*Skip Ad*' -- that string is not present in the UIA tree) Detection: lightweight eval-js polling reads classList + offsetHeight (no DOM mutation, no isTrusted concern). State JSON: {ad,skip,overlay}. Action: when ad+skip are both visible, run 'wkappbot a11y invoke <grap>#*skip-button* --timeout 8 --force'. Success = '[STATE CHANGE DETECTED]' or 'REMOVED' line in output (the 'skip-ad' Group disappears from UIA tree). Overlay close: '#*overlay-close*' wildcard for ytp-ad-overlay-close-button. Timeout discipline: keep --timeout >= 8s. The original 3s default was too tight on cold UIA tree; original suggest report ('LAUNCHER timeout 3s') was a timeout issue, not a path issue. Fixed 2026-05-21: switched from JS .click() (blocked by isTrusted) to UIA invoke (trusted). Verified on Rick Astley video with mid-roll ad: invoke caused state change + adShowing flipped false.
  2. Added 'ending' detection (video in last 2s) + preemptive mute before next ad fires (2026-05-21)
  3. UNIFIED AD DETECTION: var isAd = document.documentElement.classList.contains('ad-showing') || !!document.querySelector('.ytp-ad-player-overlay-layout'); covers both mid-roll (ad-showing) and end-roll (overlay-layout). Reload strategy: location.href = '?v='+vid+'&t='+(currentTime+0.1)+'&end='+(dur-0.1)+'&_clipped=1'
  4. COMPLETE STRATEGY (2026-05-23): (1) End-roll detected (ytp-ad-player-overlay-layout) -> reload t=dur-1 end=dur-0.1 + pauseVideo() -- no ad, paused state. (2) Mid/pre-roll (ad-showing) -> reload currentTime+0.1s -- jumps past ad cue point. (3) Premium banner -> invoke #dismiss-button. (4) Clip playback (clip= param) -> skip all processing. (5) Infinite end-roll loop prevention: &end=dur-0.1 is the key param.
  5. KEY FINDING (2026-05-23): mid-roll ads at t=451/1843 showed overlay=true but ad-showing=FALSE. Both detection methods needed: var isAd=document.documentElement.classList.contains('ad-showing')||!!document.querySelector('.ytp-ad-player-overlay-layout'). Skip first via invoke, fallback to reload.
  6. NO-CDP MODE (2026-05-25): wkappbot a11y works without CDP for Edge. Use {proc:'msedge'} grap (no cdp port needed). WinEventHook via ctypes (no pywin32) for efficient change detection. Hot-swap via os.execv on mtime change. JS reload fallback via address bar settext+invoke on Chrome_OmniboxView.
  7. NO-CDP GRAP LESSONS (2026-05-25 live investigation): (1) SHORT FORM FAILS: #But_skip-button alone returns 'UIA scope not found'. Must root path from Gro_movie_player. (2) :N SUFFIXES ARE DYNAMIC: inspect shows skip-button:19 then skip-button:1p on next ad -- these are tree traversal indices, NOT stable AutomationIds. (3) CORRECT PATTERN: a11y inspect Gro_movie_player first -> grep for skip-button line -> extract Gro_X:N/Gro_Y:N/But_Z:N path -> a11y invoke that full path. This is the 'inspect-parse-invoke' pattern. (4) NEVER PUT hwnd/pid IN GRAP: use domain: or proc: only. hwnd changes every Edge session. (5) REQUIREMENT per user: dynamic UIA info (hwnd, :N indices) must NOT be hardcoded in selectors -- always re-inspect to get current path.
  8. AD STATE DETECTION (2026-05-25): When ad is playing but skip button not yet available, skip-ad Group still exists but has ltwh=0,0,0,0 and NO Button skip-button child. When skip becomes available: skip-ad has real ltwh (e.g. -2101,165,165,55) AND Button skip-button child appears. Script logic: check if skip-button child exists before invoking. If skip-ad ltwh=0,0,0,0 -> wait and retry (ad countdown not done yet). Non-skippable ads: skip-ad Group may remain 0,0,0,0 for entire ad duration.
  9. URL-REDIRECT SKIP STRATEGY (user idea 2026-05-25): When non-skippable ad plays (skip-ad ltwh=0,0,0,0 for >15s), navigate to same URL with &t=0.1 appended. Repeat once more (double-reload). YouTube ad server skips ad on 2nd hit of same session. Implementation without CDP: (1) a11y find Edge address bar -> set-value to current_url + '&t=0.1' -> invoke (press Enter). Or use keyboard Ctrl+L -> type URL -> Enter via wkappbot. Current URL readable from window title (has video ID) or from a11y address bar value.
  10. PLAYBACK-POSITION JUMP: Ad detected + skip unavailable -> read UIA Button text (pattern: 'X min Y sec / Z min W sec') from movie_player to get current seconds -> navigate to same URL + &t=Xs. URL from Edge address bar a11y value. Set new URL via address bar set-value + invoke (no CDP). Resume from exact playback position user was at.
  11. ADDRESS BAR HOOK (smart activation): Instead of polling _youtube_in_edge() every 5s, set WinEventHook on Edge address bar (omnibox). EVENT_OBJECT_VALUECHANGE or EVENT_OBJECT_NAMECHANGE fires on URL change. Callback: parse new URL -> if youtube.com activate ad watch, else idle. Find omnibox hwnd via a11y find {proc:msedge} --text '*omnibox*' or cls:OmniboxViewViews. Hook only that hwnd pid. Zero polling overhead when not on YouTube.
  12. TITLE-CHANGE HOOK (correct smart activation): Address bar is Chrome-rendered (unreliable). Instead, hook EVENT_OBJECT_NAMECHANGE on Edge main window (Chrome_WidgetWin_1) -- this is a native Win32 title, fires on every navigation. In callback: GetWindowTextW(hwnd) -> check 'youtube' in title -> update _yt_active flag immediately. No 5s polling needed. If youtube detected -> set _event_flag to trigger ad check. Eliminates _youtube_in_edge() entirely.
  13. v1.4 URL redirect: when _find_skip_path() detects ltwh=0,0,0,0 on skip-ad node, return sentinel LTWH_ZERO (not None). try_skip() calls _navigate_skip() on LTWH_ZERO: Ctrl+L focus address bar, Ctrl+C copy URL, append ?t=0.1 or &t=0.1 via clipboard, Ctrl+A+V+Enter to navigate. Functions: _find_edge_youtube_hwnd() via EnumWindows title match, _get_clipboard()/_set_clipboard() via CF_UNICODETEXT ctypes, _keybd(vk,flags) via keybd_event. REDIRECT_COOLDOWN=15s guard prevents rapid-fire. Skip-already-has-t= guard avoids infinite loop.
  14. NAMING: call this process 'YouTube watcher' (유튭와쳐 in Korean) -- NOT 'daemon' (데몬). User finds 'daemon' confusing. In Korean responses, always say 유튭와쳐.
  15. v1.5 mouse-burst: WH_MOUSE_LL global mouse hook (SetWindowsHookExW id=14). On WM_LBUTTONUP (0x0202), sets _mouse_active_until=now+20s and fires _event_flag. Main loop polls every MOUSE_BURST_POLL=1.0s during burst window instead of POLL_S=5s. Hook installed alongside WinEventHook; both unhooked in finally. _make_mouse_cb() returns _MouseHookProc callback, stored as module-level _mouse_cb to prevent GC.
  16. v1.6 fix: WH_MOUSE_LL must run in a dedicated daemon thread with its own GetMessageW loop. Installing in the main thread causes mouse freeze because the main thread blocks inside try_skip() (8s timeout) without pumping messages. Fix: _mouse_hook_thread_fn() calls SetWindowsHookExW then loops on GetMessageW -- hook fires immediately. Main thread no longer needs to install/unhook the mouse hook.
  17. v1.6 simple-poll: removed WH_MOUSE_LL entirely (caused mouse freeze). Changed POLL_S=5 to POLL_S=1 for YouTube-active state. No mouse hook, no burst logic. Poll every 1s when yt active, 60s when idle. Skip detection latency: max 1s.
  18. v1.6 event-driven: removed WH_MOUSE_LL global mouse hook (caused system-wide mouse freeze). Now uses existing WinEventHook SHOW(0x8002)+STATECHANGE(0x800A) events with 2s cooldown to trigger skip checks.
