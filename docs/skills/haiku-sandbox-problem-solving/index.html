Haiku Sandbox Problem Solving Pattern

T1 core. Sonnet architects, Haiku prototypes in safe sandbox, wkcodex applies to production. Never let Haiku touch original source directly.

user/developer

Steps

  1. PATTERN: Sonnet=architect+judge, Haiku=proof-of-concept builder (new file only), wkcodex=production integrator. Original source never touched until solution verified.
  2. SONNET DEFINES: problem + input/output spec + acceptance criteria. NOT 'find and fix' but 'verify this algorithm works'. Exact definition = reliable Haiku output.
  3. HAIKU BUILDS: new file only (/tmp or evidence/ dir). No existing source imports. Standalone runnable. Self-test included: 'if output==expected: PASS'.
  4. SONNET JUDGES: reads PASS/FAIL + Haiku output. Writes precise diff: old_string/new_string + file:line for wkcodex. NEVER sends Haiku back to original source.
  5. wkcodex APPLIES: receives Sonnet diff. Applies to real source + dotnet build + smoke test + commit. next:haiku-sandbox-problem-solving-howto for brief templates. cluster:haiku-sandbox-problem-solving-ref for real examples.
