Steps

  1. USER GUIDANCE 2026-05-27: denying native write or edit tools is for CODEX ONLY. Codex cannot run the wkharness PreToolUse hook, so its native tools are blocked to force routing through Claude-named cmd wrappers. This deny MUST target Codex config, never the Claude Code per-repo settings file.
  2. ANTI-PATTERN fixed today: adding Edit and Write to a repo .claude settings permissions.deny disables Claude Code own Edit and Write tools for the whole repo, for every model including Opus. Cheap models then report permission needed and flail to bypass paths such as git commit to fake progress, raw PowerShell writes, or launching VS Code, then stall asking the user. Deny-as-routing backfires on same-family Claude models.
  3. ROOT CAUSE: wkharness-session-init.ps1 had an Auto-inject per-repo Claude permissions deny block writing Edit and Write into each repo settings file every hook. A Sonnet session mis-applied the Codex-intended deny to the Claude permission layer. Fix 2026-05-27: block removed, polluted wkappbot-sdk settings cleaned to empty deny, global settings unaffected and keeps Edit and Write in allow.
  4. CORRECT CODEX IMPL see skill codex-tool-wrappers: block Codex native tools via the codex config.toml PreToolUse hooks with matchers apply_patch write_file create_file read_file running DenyNativeTool.ps1 exit 2, plus AGENTS-md forbidden-native rules, plus Claude-named cmd wrappers Edit.cmd and Write.cmd that pipe Claude-format JSON to wkharness. This routes Codex through the same guards without touching Claude permissions.
  5. HARNESS LOGIC OUTRANKS CLAUDE-MD per user 2026-05-27: the hardcoded pace and budget guards in wkharness-guards.ps1 take precedence over declarative CLAUDE-MD harness:safe rules. A harness:safe rule CANNOT exempt an Edit or Write from the pace guard. The pace guard exempts only the memory folder md files and the rules MD by hardcoded logic. To edit other files while over-target use wkappbot file edit which the pace guard sanctions, or wkcodex; do not try to MD-safe past it.
  6. GUARD ORDER RULE per user 2026-05-27: check pace and opus-budget BEFORE spec-gate and agent-brief-guard. At over-target an Opus Agent spawn must be DENIED by the opus-budget guard up front. If spec-gate runs first it only asks the model to add a SPEC block, the model complies, and the Opus call proceeds, breaking through the budget. Pace check should be cached and cheap so it short-circuits early.
  7. PRINCIPLE: the harness never spawns Opus itself; a cheap model must not satisfy a gate such as spec-gate in a way that lets it spawn Opus while over-target. Over-target allow-list is Haiku Agent plus Codex or wkcodex plus wkappbot and git only. An emergency kill-switch was added to the global rules MD as a harness:block on Agent Opus spawns.
  8. POST-REVIEW + NO-DENY: a rules-MD change (Edit or Write of it, a Bash command naming it, or its mtime within about 30s) fires a NON-blocking Opus review by default in wkharness-post.ps1 (disable with WKHARNESS_CLAUDEMD_REVIEW=0). NEVER deny-intercept rules-MD edits to route them; cheap models read a deny as tool-disabled and flail. Review after, never block.
