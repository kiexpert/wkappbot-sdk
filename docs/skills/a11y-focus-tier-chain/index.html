a11y focus: SmartSetWindowOrder + full tier chain (v6.8+)

WKAppBot complete OS-level focus service spec. SmartSetWindowOrder is the single focusless Z-order primitive — called before all interactive write actions and focus commands. Zero keyboard-focus steal from user at all times.

Steps

  1. SMART WINDOW ORDER — SmartSetWindowOrder(hwnd) [A11yCommand.WindowActions.cs] WKAppBot's single focusless Z-order primitive. Never steals keyboard focus. Full OS-level focus service in 6 steps: (1) GetParent chain walk → find root ancestor (up to 32 levels, stops at IntPtr.Zero). (2) Iconic root → ShowWindow(SW_SHOWNOACTIVATE=4) BEFORE any Z-order op. SW_SHOWNOACTIVATE restores window state without activating/stealing focus. (3) MDI/child window (root != hwnd) → BringWindowToTop(hwnd). Z-order is parent-relative for child windows; BringWindowToTop brings to front of siblings. (4) PlaceRootBehindForeground(root): strip WS_EX_TOPMOST via SetWindowPos(HWND_NOTOPMOST) if set, then SetWindowPos(insertAfter=fg, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE) → root rank 2. If no fg window, insertAfter=HWND_TOP. Stripping topmost is critical — without it, topmost windows stay above ALL non-topmost windows regardless of rank-2 placement. (5) Owner chain: GetWindow(root, GW_OWNER) walk up to 8 levels. Each owner: iconic→restore, then PlaceRootBehindForeground. Owner chain uses GW_OWNER, NOT GetParent — popup/dialog owners are linked via owner relationship, not parent-child. (6) Result: target window (or its root) is at Z-order rank 2 behind user's active window. User's foreground app remains rank 1 and keyboard focus is never transferred.
  2. WINDOW-LEVEL FOCUS — A11yFocus(hwnd, tag) [A11yCommand.WindowActions.cs] Called when action='focus' targets a window (not a UIA element). (1) IsIconic(hwnd) → ShowWindow(hwnd, SW_RESTORE=9). Restore before Z-order. (2) SmartSetWindowOrder(hwnd) — full 6-step OS focus service above. (3) Log: '[A11Y] focus tag -- BringWindowToTop (child) + root behind-fg NOACTIVATE' OR '[A11Y] focus tag -- SetWindowPos behind-fg NOACTIVATE (root)' Note: SW_RESTORE (9) used here (not SW_SHOWNOACTIVATE=4) because A11yFocus is the explicit focus command — restoring to normal state is expected. SmartSetWindowOrder handles owners/topmost.
  3. ELEMENT-LEVEL FOCUS — A11yFocusElement(el, hwnd) [A11yActions.Focus.cs] Called when action='focus' targets a UIA element. Full 5-tier cascade: Tier -1 (PRE): FindRootWindow(hwnd) → SmartSetWindowOrder(root). FindRootWindow: walks GetParent up to 32 levels to find root ancestor. Ensures window is visible in correct Z-order before focus attempt. Tier 0 (CDP): Chrome/CDP only. TryCdpFocus() calls SmartSetWindowOrder(hwnd) first, then CDP element.focus() / defA11yFocus() JS helper (blur active, focus editor). Returns 'focused:<selector>' on success. Falls through on failure. Tier 1 (UIA): el.Focus() via IUIAutomationElement::SetFocus. Focusless cross-thread. Logs '[A11Y] focus -- UIA SetFocus -> [ControlType] name'. Tier 2 (Win32): GetElementHwnd(el) → Win32 SetFocus(elementHwnd). Direct Win32 keyboard focus on the specific control hwnd. Tier 3 (Win32 root fallback): if element hwnd missing AND UIA failed → Win32 SetFocus(rootHwnd). Last resort.
  4. WRITE ACTION PRE-FOCUS — A11yCommand.cs element dispatch [v6.8+] SmartSetWindowOrder(hwnd) is called BEFORE these 10 interactive write actions: invoke, click, type, set-value, set-range, toggle, expand, collapse, select, scroll EXCLUDED (SmartSetWindowOrder NOT called): read, find, inspect, screenshot, ocr, windows — read-only, no Z-order change needed close, minimize, maximize, restore — Z-order change would interfere highlight, focus — own handling (focus calls SmartSetWindowOrder internally) This ensures the target window is at correct Z-order (rank 2) before automation, without ever disrupting the user's active window (rank 1 unchanged).
  5. ZERO-STEAL RULES (absolute, no exceptions): FORBIDDEN: SetForegroundWindow, SetActiveWindow, AttachThreadInput — all steal keyboard focus. ALLOWED Z-order: SetWindowPos(SWP_NOACTIVATE), BringWindowToTop (child only), ShowWindow(SW_SHOWNOACTIVATE=4). ALLOWED keyboard focus: UIA el.Focus(), Win32 SetFocus(elementHwnd) — these set input focus on a specific control without changing the foreground window. Safe for automation. SWP_NOACTIVATE ensures Z-order moves never trigger WM_ACTIVATE or WM_SETFOCUS on target. BringWindowToTop on a child window is safe — Z-order is parent-relative, no desktop steal. PlaceRootBehindForeground always places at rank 2 — user's rank 1 window untouched. ShowWindow(SW_SHOWNOACTIVATE) restores iconic windows without activating them.
  6. OVERLAY GUARD + SOURCE FILES SuppressFullscreenOpaqueOverlays [A11yCommand.WindowActions.cs]: pre-check on every a11y command. Samples 5 pixels (center + 4 quadrant centers) on every visible window >= 80% work area. avg brightness < 80/765 → force alpha=0 (WS_EX_LAYERED) OR SW_MINIMIZE (non-layered). Same HWND suppressed >= 4 times → kill the process. Logs [OVERLAY-GUARD] to stderr. Handles: NVIDIA GeForce Overlay, TextInputHost, and any unknown black fullscreen overlays. SOURCE FILES: A11yCommand.WindowActions.cs — SmartSetWindowOrder, PlaceRootBehindForeground, A11yFocus, SuppressFullscreenOpaqueOverlays A11yActions.Focus.cs — A11yFocusElement, FindRootWindow, TryCdpFocus A11yCommand.cs:1907 — write action pre-focus injection (10 actions)
  7. FOCUSLESS-FIRST PRINCIPLE (cross-ref: skill focusless-first-principle): UIA Invoke/SetValue/Toggle/Select/Scroll are inherently focusless — no window activation needed. SendInput and WM_CHAR (some) require keyboard focus. SmartSetWindowOrder (Z-order) is separate from keyboard focus — you can have correct Z-order (rank 2) without keyboard focus. The focus tier chain (Tier 0-3) sets keyboard focus on the element; SmartSetWindowOrder ensures the window is visible. Both are focusless from the USER's perspective — the user's active window (rank 1) is never disrupted.
  8. COMMON PITFALLS: DON'T use SetForegroundWindow — steals keyboard focus, triggers WM_ACTIVATE, disrupts user. DON'T use BringWindowToTop on root windows — use PlaceRootBehindForeground instead. DON'T skip topmost strip — if WS_EX_TOPMOST is set, rank-2 placement has no effect. DON'T assume GetParent == owner — popup/dialog owners use GW_OWNER (GetWindow), not GetParent. DON'T skip iconic check inside SmartSetWindowOrder — child BringWindowToTop on a minimized parent creates a ghost MDI entry with no visible surface. DO always pass SWP_NOACTIVATE with SetWindowPos Z-order changes. DO call SmartSetWindowOrder before element focus tiers (Tier -1 in A11yFocusElement).
