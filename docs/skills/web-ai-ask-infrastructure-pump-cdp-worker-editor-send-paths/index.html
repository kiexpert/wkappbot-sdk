Web AI Ask Infrastructure: Pump, CDP Worker, Editor Send Paths

Architecture of the page-side JS pump worker and C# orchestration layer for sending prompts to web AI (Claude/GPT/Gemini). Covers editor types, send path hierarchy, CDP_SIGNAL, cross-prompt delivery, attachment lock, and watchdog.

Steps

  1. 1. [PUMP ARCHITECTURE] window.__wkAskPump = singleton JS object injected into each AI tab via CDP Runtime.evaluate. One setInterval(500ms) per editor selector. Hash-based change detection: content hash changes ??ticks=0 (reset); hash stable for 2 ticks (1s) ??trySend(). C# side: CdpPromptPump.cs (AppendAndQueueAsync ??ArmPromptPumpAsync ??CDP_SIGNAL poller). Key timing: trySend() fires ~1.5s after first stable content (first tick resets hash=0?뭜, second+third ticks count stable). FlushPromptPumpNowAsync() calls trySend() immediately, bypassing timer.
  2. 2. [trySend() SEND PATH HIERARCHY] 5-tier fallback in order: (1) form.requestSubmit() ??cleanest, works for standard forms; (2) send button click ??querySelector data-testid/aria-label/send-button/[type=submit]; (3) JS KeyboardEvent(Enter) dispatchEvent on editor ??works for tiptap/textarea, IGNORED by ProseMirror; (4) CDP_SIGNAL ??last resort: sets st.readyToSend=true and returns 'CDP_SIGNAL', C# polls and fires CDP Input.dispatchKeyEvent Enter. IMPORTANT: ProseMirror editors (Claude.ai, ChatGPT) reject JS keyboard events ??CDP_SIGNAL is always the active path for them.
  3. 3. [EDITOR TYPES BY AI] Claude.ai: div.tiptap.ProseMirror (contenteditable=true) ??ProseMirror. ChatGPT: #prompt-textarea (ProseMirror variant, contenteditable div). Gemini: div[contenteditable=true] in rich-textarea ??tiptap/ProseMirror-like but accepts JS KeyboardEvent in some versions. All are contenteditable divs, NOT textarea. GetTextLengthAsync reads el.innerText.length. CONSEQUENCE: form.requestSubmit() may not exist; JS KeyboardEvent is unreliable ??CDP_SIGNAL path is the reliable fallback for all ProseMirror editors.
  4. 4. [CDP_SIGNAL FLOW] When trySend() returns 'CDP_SIGNAL': (a) JS sets st.readyToSend=true; (b) C# CdpPromptPump.AppendAndQueueAsync spawns background Task that polls CheckPumpReadyAsync() every 300ms 횞 13 iterations (~4s window); (c) on detection, fires cdp.SendPromptAsync(editorSel) ??CDP Input.dispatchKeyEvent{key:Enter}; (d) CheckPumpReadyAsync atomically clears st.readyToSend=false. Race safety: after SendPromptAsync fires, editor content is cleared ??DebateRunner.SendPendingCrossPromptAsync (editorLen > 10 check) returns false = no double-send.
  5. 5. [CROSS-PROMPT DELIVERY ??TWO PATHS] For triad/cross-prompts (e.g. Gemini?묬laude): PATH-A (primary): CDP_SIGNAL poller fires ~1.5s after arm ??SendPromptAsync; PATH-B (safety net): DebateRunner.SendPendingCrossPromptAsync() runs after AI response completes (line ~1029 AskCommands.DebateRunner.cs) ??checks editorLen > 10 ??SendPromptAsync. In practice PATH-B fires later (AI response takes 10-30s+) and editor is already empty from PATH-A ??PATH-B is a no-op. Both paths are always running concurrently; no double-send because PATH-A empties editor before PATH-B checks. Log marker: '[CROSS:{ai}] Found pre-typed cross-prompt ({n} chars) ??sending'.
  6. 6. [ATTACHMENT TRANSACTION LOCK] When file attachment is needed before prompt: (1) BeginAttachmentLockAsync: sets C# PageState.Locked=true + JS st.locked=true ??pump stops auto-fire; (2) chunks arriving during lock go into PageState.QueuedChunks; (3) CompleteAttachmentLockAsync: appends queued chunks + unlock + FlushPromptPumpNowAsync (immediate trySend, bypasses timer); (4) AbortAttachmentLockAsync: unlock + optional queue clear. Purpose: ensure attachment uploads complete before prompt fires. File: AskCommands.CdpPromptPump.cs.
  7. 7. [PLACEHOLDER vs DRAFT BUG ??NON-CRITICAL] GetTextLengthAsync reads el.innerText.length. ProseMirror may render placeholder text as actual innerText (not just CSS ::before) on some versions ??pump/watchdog can misidentify placeholder as user draft. Symptom: DebateRunner logs 'Found pre-typed cross-prompt' but content is placeholder. Fix direction: compare against data-placeholder attribute or check if el.classList contains a 'is-empty'/'placeholder' class before acting. Status: tracked, non-critical since it only causes spurious Enter keypresses on empty-ish editors.
  8. 8. [SUBMIT WATCHDOG + TICK LOGGING] Watchdog (in AppendAndQueueAsync): two-phase check ??GetTextLengthAsync at t=3s (first), then at t=5s (second). If first<=0 or second<=0 ??already submitted ??OK. If second<first ??submission in progress ??OK. If second>=first ??editor still has content ??AutoRegisterBug(msg). Prevents silent pump failures. Tick logging: console.debug('[PUMP] content changed/stable tick/trySend result') per interval tick. C# logs: '[ASK:PUMP:{Name}] {scope} [{targetId}]: armed|arm-failed|CDP_SIGNAL?뭚iring CDP Enter'. Key file refs: CdpClient.AiHelpers.cs (ArmPromptPumpAsync, CheckPumpReadyAsync, FlushPromptPumpNowAsync), AskCommands.CdpPromptPump.cs (AppendAndQueueAsync, BeginAttachmentLockAsync, CompleteAttachmentLockAsync), AskCommands.DebateRunner.cs (SendPendingCrossPromptAsync ~line 1004).
