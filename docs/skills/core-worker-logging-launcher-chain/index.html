WKAppBot Logging Architecture: Core Workers, Launcher Relay, Error Guarantees

Past Core workers toiled tirelessly yet left no logs — their labor unrecorded, their struggles invisible. Complete guide to WKAppBot's layered logging: worker self-log, Launcher relay buffering, error flush guarantees, and errors.jsonl fallback chain.

Steps

  1. ARCHITECTURE OVERVIEW: Three layers — (1) Core TeeTextWriter (primary), (2) Launcher relay buffer (fallback), (3) Worker self-log (no-Launcher spawns). All three must cooperate for zero blind spots.
  2. LAYER 1 — Core TeeTextWriter: created when Launcher manages process (tee != null). Tees stdout to log file, tracks [TAG] fields, calls WriteErrorRecordNow() on non-zero exit → errors.jsonl. ErrorScope buffers stderr with timestamps during command execution.
  3. LAYER 2 — Worker self-log (v5.13.133): when tee==null AND IsLauncherInParentChain()==false → Core creates WorkerStderrTeeWriter at startup. Tees stderr to log file. Covers Eye-spawned workers (claude-proxy, whisper-ring, analyze-hack) that bypass Launcher.
  4. LAYER 2 check logic: IsLauncherInParentChain() walks WMI Win32_Process ancestor chain. wkappbot.exe found → Launcher active → skip. Not found → self-create log. Eye-internal routes (EyeCmdPipeServer in-process) also return true (Eye's ancestor includes Launcher).
  5. LAYER 3 — Launcher relay fallback (v5.13.136): Launcher buffers last 20 stderr lines + captures [LOG] path. On Core non-zero exit → AppendLauncherErrorRecord() writes {source:launcher} entry to errors.jsonl. Covers Core crashes before TeeWriter setup.
  6. Silent swallow (exit 0 + errors): code==0 AND errorDetected AND StdoutIsBlank → silentSwallow=true → forceErrorLog + AutoRegisterBug('[BUG-AUTO]...'). NEVER change exit code — downstream may depend on 0.
  7. errors.jsonl entry sources: 'core' (TeeTextWriter) vs 'launcher' (Launcher fallback). Both may exist for same crash — that's fine. Core entry has [TAG] field analysis; Launcher entry has raw stderr snippet.
  8. RELAY FLUSH RULE: in piped-relay mode, stderr must flush identically to standalone Core exit. Implementation: save stderrRelayTask = Task.Run(...). After WaitForExit → stderrRelayTask.Wait(2000) → THEN TerminateSelf. Core pipe closes on exit → relay task exits naturally; 2s is safety fallback.
  9. Launcher stdout loop: catch Exception explicitly and log (not silent break). WaitForExit has 5s timeout after stdout EOF — kill Core if still alive. stdout pipe error = diagnostic, not silent failure.
  10. Empty stdout + non-zero exit: [LAUNCHER] Core exited N with no stdout — check stderr log above. Alerts caller who would otherwise see only a bare exit code.
  11. Sentinel \0UIT: must be checked on RAW BYTES before any text encoding. StreamReader.ReadLine() breaks sentinel detection — always read raw bytes first, accumulate text separately in StringBuilder for line extraction.
  12. UNIFIED EXIT FUNCTIONS (v5.13.137+): Two functions own ALL exit paths — AppBotQuitFlush (Launcher) + AppBotExit (Core). Launcher: AppBotQuitFlush(exitCode, stderrRelayTask?) → stderrRelay.Wait(2000) → AppBotExit(code) → stderr dump + Console.Out/Error.Flush() + TerminateSelf. Core: AppBotExit(exitCode) returns int, then ProcessExit hook fires → Console.Out.Flush() + Console.Error.Flush() + DoRequiredExitCleanup (tee.Dispose + Console.Error.Flush() + WriteExitFile [also flushes STD_ERROR_HANDLE]) + \0UIT + TerminateProcess. Rule: no bare TerminateSelf/TerminateProcess — always go through the two-function chain.
  13. MCP LOOP EXIT: McpCommand returns before TeeWriter setup (MCP must own stdout). No _activeTee → DoRequiredExitCleanup is no-op for tee. Exit path: return 0/1 → Main() → AppBotExit(code) (ErrorScope flush) → finally/DoRequiredExitCleanup → ProcessExit → Console.Error.Flush() → \0UIT → TerminateProcess. The Console.Error.Flush() in ProcessExit hook is critical for MCP — it ensures trailing log lines written inside McpCommand (e.g. '[MCP] Fatal: ...') are not lost when TerminateProcess kills the process. Without it, the last few stderr bytes may sit in .NET's internal TextWriter buffer and never reach the pipe.
  14. [DEV] Implementation: IsLauncherInParentChain() in Program.cs — WMI Win32_Process ancestor walk (max 10 levels). WorkerStderrTeeWriter sealed class tees stderr to log file. AppBotQuitFlush() in CoreRunner.cs wraps stderrRelay.Wait(2000)+AppBotExit(code).
