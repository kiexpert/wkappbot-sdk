Standard Chrome Window: CDP tab to root browser window, multi-tab, iconified, placement

Chrome-side parallel to standard-appbot-window. How to correctly identify and move the Chrome browser window for CDP placement. Covers tab vs window, multi-tab, non-active tab, iconified Chrome, and all edge cases. Read alongside standard-appbot-window.

user/developer

Steps

  1. Chrome tab != root window. Browser.getWindowForTarget({targetId}) returns root OS browser window. ALWAYS pass targetId explicitly -- default session may return wrong window in multi-tab.
  2. SetWindowBoundsAsync: 2-step for minimized Chrome -- (1) setWindowBounds windowState=normal (2) WaitForWindowStateAsync until normal (3) set actual bounds. Chrome ignores setBounds while minimized.
  3. DPI: Browser.setWindowBounds uses PHYSICAL pixels. PerMonitorV2 process shares coord space with Win32 GetWindowRect. No conversion needed. ClampBoundsToVisible is last-resort safety net.
  4. Target class = Chrome_WidgetWin_1 (top-level, unowned GW_OWNER==0). NOT Chrome_BrowserWindow -- legacy/internal, unsafe for SetWindowPos.
  5. DANCING = self-inflicted by repeated corrective SetWindowPos racing Chrome layout. Fix: place ONCE after window visible/idle via Browser.setWindowBounds. next:standard-chrome-window-howto for tab/multi-tab/minimize details. cluster:standard-chrome-window-ref for DPI audit + bug history.
