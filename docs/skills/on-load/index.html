On Load (T1 core)

T1 core tier. Session-start decision rules: when to run mandatory loads, gg trigger, bare-keyword routing. Execution detail -> wkappbot skill read on-load-howto. History -> wkappbot skill read on-load-ref.

Steps

  1. WHEN TO RUN. (A) session start or post-compaction -> load mandatory skills (see on-load-howto step 1) + run handoff (on-load-howto step 3) + run suggest backlog (on-load-howto step 4). (B) user sends exactly gg or ggg -> run GG TRIGGER (T1 step 2). (C) mid-task or casual greeting -> SKIP full pipeline.
  2. GG TRIGGER. User message exactly gg or ggg -> locate the gg Main Workflow section in project root markdown rules file and execute every step sequentially end-to-end NO confirmation, finish with repo-health-doctor. If section missing: ask user for recurring tasks, add the gg Main Workflow section, then run it same session. Quota/limit error: mark handoff_pending, do NOT retry same CLI.
  3. BARE KOREAN KEYWORD RULE. If user drops an isolated Korean keyword or short phrase, run wkappbot skill search term FIRST. Never guess intent before the skill search resolves a matching skill.
  4. NAVIGATION. Execution details (commands, mandatory loads, agent rules, file-edit discipline, skill-edit discipline, TODO sync) -> wkappbot skill read on-load-howto. History or incident notes or dated bug accumulation -> wkappbot skill read on-load-ref. Both are part of this cluster.
  5. SELF-AUDIT POINTER (Opus sessions): at the END of substantive work, before wrapping a session, or after compaction, run the self-reflection audit. Read wkappbot skill read opus-self-reflection (the Opus memoir plus end-of-work checklist: did I skillify what I learned, is it findable, did I tier fat skills, did I avoid bandaids and backdoors, did I propagate to posterity). It pairs with sonnet-bug-stop-policy on the Sonnet side. The whole fleet learns from each session honest reflection.
  6. INPUT REFLEXES (bare-key shortcuts -- be precise about single vs double, the user types the Korean giyeok key): EXACTLY ONE giyeok ㄱ sent alone means YES -- accept the assistant most recent proposal and CONTINUE the current in-progress task. Do NOT restart the workflow on a single ㄱ. TWO or more (ㄱㄱ or ㄱㄱㄱ, or gg or ggg) means RESTART -- run the gg Main Workflow in the project CLAUDE.md from the top. Count the giyeok: one is continue, two-plus is restart. If it is ambiguous which the user meant, ASK before restarting, because restart discards the current working context.
  7. KNOWLEDGE-IFICATION (jisikhwa) TRIGGER: when the user utters the knowledge-ify keyword (Korean jisikhwa, alone or with a go particle), read knowledge-ification-procedure-jisikhwa and 3-tier-skillify THIS session experience plus process by default (T1 core, T2 howto, T3 ref). Authoritative route is the CLAUDE.md jisikhwa Shortcut (global + project). Concept defs: ki-concept-definitions. Do not flounder; skill search jisikhwa also finds it.
  8. LOW-PACE DEFERRED-BUILD EXECUTION (2026-06-04): harness builds get deferred when pace runs over the prorated target (this session ran ~3x ahead of pace, throttling all Edit/Write even for subagents). RESUME them only when pace is UNDER target -- a low-usage session, or later in the week once the prorated target rises above current usage. NOTE: the Thursday 07:00 KST reset alone is NOT the trigger -- a fresh week front-loaded by a heavy session is still over-pace. When pace is under target, execute deferred builds CHEAP-FIRST: dispatch Haiku or Codex via Agent.cmd to prototype per the build-plan skill, then verify (powershell -Test or Parser ParseFile syntax check), and Opus ONLY commits, never Opus-direct edit. Currently deferred (pace-blocked): watchdog-harness-keep-build and command-start-anchor-fix-build (build-plan skills hold exact files, old/new strings, selftest pairs). At session start, check pace; if under target and these remain unbuilt, prototype them cheap-first. This is cheap-first discipline applied to deferred work.
