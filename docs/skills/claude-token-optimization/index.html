Claude Token Optimization — Exploration, Context & Search

80-90% of tokens are spent on file exploration, not writing code. Techniques: (1) skill-search-first prevents redundant Glob/Grep. (2) .claudeignore + lean CLAUDE.md + session mgmt saves 30-40%. (3) PreToolUse hook enforces search discipline globally. (4) Codebase pre-indexing saves 90%+ of exploration tokens. (5) 3-agent team eliminates scope creep.

Steps

  1. [SKILL-SEARCH-FIRST] MANDATORY before any Glob/Grep/Read for knowledge lookup: run wkappbot skill search <keyword> first. Skills cover *** -- almost all WKAppBot knowhow lives in skills. Anti-pattern (FORBIDDEN): Glob/Grep without prior skill search = direct CLAUDE.md violation.
  2. [PRETOOLUSE-HOOK] Enforce skill-search discipline globally via settings.json PreToolUse hook. In ~/.claude/settings.json add hook on Bash, Glob, Grep tools that prints: SKILL SEARCH FIRST: wkappbot skill search <keyword>. This fires even for unconfigured Claude sessions. JSON path: hooks[PreToolUse][].matcher=Bash or Glob or Grep, type=command.
  3. [CLI-SKILL-HINT] PrintSkillSearchHint() embedded in WKAppBot CLI exploratory output. Added to: wkappbot windows (no filter), a11y find */ inspect * (wildcard). Prints '# SKILL SEARCH FIRST: wkappbot skill search <keyword>' before results. Any Claude session -- even unconfigured -- sees the reminder. Source: InspectionCommands.cs.
  4. [CLAUDEIGNORE] Create .claudeignore in project root. Exclude: node_modules/, dist/, bin/, obj/, .bak/, .log, .out, .wkappbot/, .dotnet/. One-time setup, no maintenance needed.
  5. [CLAUDEIGNORE-HQ] WKAppBot-specific .claudeignore for HQ runtime noise -- prevents large screenshot/log dirs entering context: bin/wkappbot.hq/experience/, bin/wkappbot.hq/logs/, bin/wkappbot.hq/runtime/, bin/wkappbot.hq/data/, bin/*.bak-*.exe, bin/*.old-*.exe, bin/*.new.exe. Add similar patterns for any project with large generated runtime directories.
  6. [CLAUDE-MD-200] CLAUDE.md hard cap = 200 lines. Every conversation loads it in full. Over limit: use Opus agent to trim (Agent model=opus prompt='trim CLAUDE.md to 200 lines, preserve all rules, move details to memory/ topic files'). Check with wkappbot claude-usage.
  7. [SESSION] Use /compact when conversation grows long. Use /clear when switching to a completely new task. Check context with wkappbot claude-usage -- handoff at 8MB, urgent at 10MB.
  8. [MCP] Only connect MCP servers you actively use. Each connected server adds tool definitions to every message. Disconnecting 3 unused servers gives immediate relief.
  9. [QMD-MODES] Three search modes: (1) qmd search = BM25 keyword/identifier, fast, no extra models. (2) qmd vsearch = vector semantic, concept queries. (3) qmd query = hybrid+LLM expansion, downloads 2GB models first run. Use search for identifiers, vsearch for concepts, skip query in daily use.
  10. [QMD-TIPS] Search without --collection searches all collections at once. Exact function names return precise file:line. Natural language works best with vsearch. Add qmd server to .mcp.json, available as mcp__qmd__* tools.
  11. [3-AGENT] Split work into 3 roles: (1) Architect reads codebase, writes detailed brief. (2) Builder implements ONLY what brief specifies. (3) Reviewer validates output, returns specific failures to Builder.
  12. [3-AGENT-WHY] Without role separation, Claude reads entire codebase for a login feature, adds untested CSS, writes unrequested tests. Builder never reads files the Architect did not specify.
  13. [CLAUDE-MD-RULES] 5 rules to embed: (1) Never re-read a file already in context. (2) No speculative tool calls. (3) Parallelize independent tool calls. (4) Never repeat what user already explained. (5) Use qmd search before reading files.
  14. [PRIORITY] Apply in order: skill-search-first + PreToolUse hook (zero cost, immediate). Then .claudeignore + lean CLAUDE.md (immediate, zero cost). Then qmd pre-indexing (5 min setup, 91% savings). Then 3-agent structure when project grows.
  15. [IMPACT] Combined: same token budget handles 2-3x more work. For Claude Pro users with tight limits, this effectively doubles monthly task capacity.
