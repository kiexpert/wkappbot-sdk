claude-proxy: Context Limit Auto-Handoff to Gemini Agent

When Claude hits context limit, claude-proxy intercepts the error and hands off to wkappbot agent gemini --new-session with CLAUDE.md + MEMORY.md + original prompt. Subsequent prompts relay via --interrupt. Claude Code sees no error.

user/developer
claude-proxyhandoffcontext-limitgeminiagentproxysession-recoveryoperator

Steps

  1. Setup: wkappbot claude-proxy --inject-context (runs on port 7788). Set ANTHROPIC_BASE_URL=http://localhost:7788 in ~/.claude/settings.json. Restart Claude Code.
  2. Normal operation: proxy is transparent glass — all requests pass through to Anthropic unchanged.
  3. Context limit hit: proxy intercepts context_window_exceeded error. Reads CLAUDE.md + MEMORY.md. Extracts original user prompt from the failed request.
  4. Handoff: proxy spawns wkappbot agent gemini --new-session with combined context: CLAUDE.md + MEMORY.md + original prompt. Returns Gemini response as fake SSE to Claude Code.
  5. Relay mode: proxy enters Gemini relay mode. Subsequent Claude Code prompts are forwarded as --interrupt to the running Gemini agent session.
  6. Weekly API limit (all Anthropic models blocked): proxy catches overload/rate-limit errors too and routes to Gemini agent same way.
  7. Claude Code UX: no error shown. Sees normal assistant response. Seamless switch from Claude to Gemini mid-session.
  8. Manual trigger: wkappbot agent gemini --new-session $(cat ~/.claude/CLAUDE.md memory/MEMORY.md) + prompt. Use when approaching limit proactively.
