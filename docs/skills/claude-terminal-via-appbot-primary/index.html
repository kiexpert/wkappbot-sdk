Claude Terminal via AppBot as Primary Workflow -- Ditch VS Code Extension for Automation

Design rationale + migration guide for running Claude Code via terminal (AppBot-mediated) instead of VS Code extension. Terminal Claude wins on: rate-limit resilience (auto-handoff to Gemini), full MCP tool access, Slack bidirectional integration, cron-safe scripting, multi-Claude orchestration. VS Code extension retains value only for active code-editing sessions.

Steps

  1. IDENTICAL CAPABILITIES: both share ~/.claude/ store (memory, sessions, skills, MCP servers), same tools, identical results.
  2. TERMINAL EDGE: rate-limit auto-handoff via claude-proxy skill; full MCP; Slack 2-way; cron-safe non-interactive; multi-Claude orchestration via agent claude; session logging via AppBot.
  3. VS CODE STILL WINS FOR: active code reading with IDE selection context + clickable file links. Rule: >50% editor use = VS Code, else terminal.
  4. MIGRATION: keep both (share state). Move cron/Slack-triggered/automation tasks to terminal first. Enable claude-proxy for transparent rate-limit handoff.
  5. CALL PATTERNS: claude -p 'q' < /dev/null ; claude --continue ; wkappbot agent claude 'task' ; wkappbot prompt send --when-idle 'task'.
  6. GOTCHAS: bot self-mention no-trigger (need xoxp-); terminal loses IDE selection; dedupe memory writes across parallel sessions.
  7. TRIGGER 2026-04-17: VS Code session hit rate limit, late Slack notification. Terminal + AppBot would have auto-routed to Gemini silently.
