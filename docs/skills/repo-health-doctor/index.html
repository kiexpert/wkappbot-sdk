Periodic repo health check covering GitHub issues (close Daily reports, triage real bugs), unanswered issue comments, empty CLAUDE.md sections (Gotchas/Skills stubs), and launch checklist progress comments. Run before release or when repo feels stale.

user/developer
repohealthdoctorissuesgithubdailyclosetriage

Steps

  1. WHEN TO RUN -- two modes: [LITE] run any time (session start, after big refactor, before committing). [FULL] run before release or when repo feels stale -- includes administrative work that costs context. Quick alias: wkappbot skill read repo-health-doctor and run only [LITE] steps for fast checks.
  2. [FULL] GitHub issues: gh issue list --state open. (A) [Daily] WKAppBot Report entries -> close all: gh issue close <n> --reason completed --comment "Closing automated daily report". (B) Real bugs -> check if fixed in recent commits: git log --oneline --since=<issue-date>
  3. grep -i <keyword>. If fixed -> close with version. If not -> comment with current status. (C) Feature requests -> comment with roadmap note or file suggest: wkappbot suggest "title".
  4. [FULL] Unanswered issue comments: for each open issue with comments, run gh issue view <n> --comments. Look for questions from contributors with no owner reply. Post: gh issue comment <n> --body "...".
  5. [LITE] CLAUDE.md empty sections: Read project CLAUDE.md. Find stub lines like '- (add project-specific gotchas here)' or '# Remove keywords that don't apply'. Actions: (A) Skills stub -> run the search line, pick top 3 relevant skills, replace stub with actual reads. (B) Gotchas stub -> scan git log and suggest list for lessons learned, fill real gotchas. (C) Build section missing -> add from actual build command.
  6. [FULL] Launch checklist (if issue #1 exists): gh issue view 1 --comments. If new items completed since last comment, post update: list completed items, update progress %, list remaining.
  7. [FULL] CHANGELOG completeness: git log --oneline since last version tag -- every meaningful commit should appear in CHANGELOG.md. Add missing entries before release.
  8. [LITE] README.md sync: version number, feature list, quickstart commands -- verify all current. Any overlap with CLAUDE.md must agree exactly. Fix both in one commit.
  9. [LITE] AGENTS.md / CLAUDE.md parity: both must agree on shared AI policy -- delegation, language, notifications, process kill. diff key sections. Fix in one commit. Codex reads AGENTS.md; Claude reads CLAUDE.md -- divergence means two AIs work under different rules.
  10. [LITE] Skill source_refs audit: wkappbot skill audit -- finds skills whose source_refs point to moved/renamed/deleted code. Fix: wkappbot skill edit <id> to update refs. Do after every file rename or module split.
  11. [LITE] gg section smoke test: actually run 'gg' and verify every step in ## gg Main Workflow executes without error. Common failures: renamed skill IDs, changed build paths, removed features in Agent prompts. Fix before committing.
  12. [LITE] Command Grounding -- gg dry-run validator: extract every binary from ## gg Main Workflow. Run where <binary> (Windows) or which <binary>. If not found: append '# [BROKEN] <binary> not in PATH' comment in CLAUDE.md. Common broken patterns: absolute paths from another machine, venv-only python, npm without node_modules, renamed wkappbot subcommands. A CLAUDE.md with [BROKEN] commands trains the AI to retry a failing pattern indefinitely -- fix or remove immediately.
  13. [FULL] CI health: gh run list --limit 5 -- all green before release. If red: gh run view <id> --log-failed. Never ship with a red CI badge -- users see it and lose trust.
  14. [FULL] Resolved suggests cleanup: wkappbot suggest list -- HALF state items done in reality -> wkappbot suggest check <ts> --confirm. Suggests describing bugs fixed in recent commits -> close with version note. Stale suggests mislead future sessions.
  15. [FULL] User-facing text audit: grep -r 'TODO\
  16. FIXME\
  17. HACK\
  18. TEMP\b\
  19. \[DBG\]' csharp/src/ --include=*.cs. Also wkappbot --help
  20. check every listed command exists and works. Fix before release -- first-time users file issues immediately on broken --help.
  21. [LITE] Cross-model format check: scan CLAUDE.md and README.md for model-specific formatting that breaks across AI contexts -- LaTeX math ($$...$$), Jupyter-style output blocks, or tool-call XML that only renders in one model. Plain Markdown only. If found: convert to standard Markdown before the next session so any AI (Claude/Gemini/Codex) can read it without confusion.
  22. HEAL NOTE (2026-05-26): SECURITY.md supported-versions table drifts behind csharp/Directory.Build.props WKAppBotBaseVersion. On version bump, update the table top row to match. README uses a release-badge for version (no hardcoded string) so it auto-tracks. Edit emoji-containing markdown tables via wkappbot file edit --old-file/--new-file (temp files), never inline shell args -- pipe-char in the table row breaks shell arg parsing.
  23. Nightly healing script executing -- auditing broken skills and compressing Pending
