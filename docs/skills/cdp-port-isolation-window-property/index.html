CDP Port Isolation via Window Property per wkappbot Instance

Each wkappbot instance binds its launched CDP port to a Window Property keyed by ProjectRoot.Hash8 on the parent console (or desktop) HWND so sibling instances cannot steal each other's Chrome via host or port scans. Strict CWD-hash isolation: ProjectRoot honors AsyncLocal CallerCwdOverride from EyeCmdPipeServer (so Eye serving sibling repos uses the actual caller's hash, not the cached first-call hash), and FindRunningChromePort matches userDataDir by exact path equality on both the WMI cmdline parse and the /json/version udd field. No more substring-contains matches; no more 'trust derived port if udd absent' fallback.

Steps

  1. On Chrome launch or detected reuse: ChromeLauncher.RegisterLaunchedPort(port) writes prop WKAPPBOT_CDP_PORT_<hash8> on GetConsoleWindow (fallback GetDesktopWindow).
  2. FindBestPortForHostAsync consults GetLaunchedPort first: only matches this instance's port; returns -1 when nothing registered so caller takes the launch path instead of stealing a sibling's Chrome.
  3. FindFirstFreePortAsync returns the registered port directly when present (no scan race with siblings).
  4. EnsureCdpConnection (AskCommands.Entry.Cdp) sets DefaultUserDataDirBase + ProjectHash BEFORE any port discovery so the registry lookup sees the correct per-project bucket.
  5. ConnectCdp (WebCommands) prefers GetLaunchedPort over the caller's default 9222 to survive cross-instance sibling registrations on the same machine.
  6. ProjectRoot.Find/Hash8 honor AsyncLocal CallerCwdOverride: when EyeCmdPipeServer dispatches an in-process command (CallerCwd.Value set), it also sets ProjectRoot.CallerCwdOverride.Value so the per-call hash is re-derived from the actual caller's CWD. The static _root/_hash8 cache is bypassed entirely on Eye-routed calls, fixing the long-running-Eye leak where every cross-repo command silently used the first caller's hash.
  7. FindRunningChromePort and KillStaleChromesAsync use CmdLineUserDataDirEquals: parses --user-data-dir=PATH from the chrome.exe cmdline and compares the canonicalized full path with strict equality. No substring contains-checks.
  8. FindRunningChromePortByCdpScan returns 0 when the probed Chrome's /json/version response lacks a userDataDir field. The previous 'trust derived port' fallback for older Chromium is removed -- it could claim a sibling Chrome whenever our derived port collided.
  9. Last-resort recovery (2026-05-25): when all CDP HTTP probes return 0 but a chrome.exe for our udd is still process-alive (renderer crash / brief hang), scan processes by cmdline udd via FindChromeProcessByUserDataDir (process-only, no HTTP), verify by ConnectAsync + Target.createTarget, reuse on success, and only kill the zombie when tab creation also fails -- prevents duplicate Chrome spawn alongside the live one.
  10. BUG FIX (2026-05-26): FindRunningChromePortAny port-file guard was causing Chrome multiplication. When disk port file is missing/expired (ReadPortFile returns 0), the guard evaluated = true, skipping ALL Chromes. Fix: change to .
