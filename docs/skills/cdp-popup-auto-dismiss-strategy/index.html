CDP popup auto-dismiss strategy: blocking overlay removal before prompt injection

How wkappbot automatically clears blocking popups (login prompts, ad modals, cookie banners on non-AI domains) before CDP prompt injection. Covers ChatGPT stay-logged-out handler, generic X-button dismiss, and AI-service exclusion rules.

Steps

  1. POPUP AUTO-DISMISS runs automatically before prompt injection in all ask flows (ask gpt, ask gemini, ask claude). Implemented in CdpClient.PopupDismiss.cs via DismissBlockingPopupsAsync(). Non-fatal -- errors are logged but never block the ask flow.
  2. STAGE 1 -- ChatGPT only (chatgpt.com): finds button/a elements matching /stay logged out
  3. continue without
  4. use as guest
  5. skip
  6. not now/i and clicks. Maintains anonymous session to avoid per-account quota tracking (see cookie-consent-ai-strategy skill).
  7. STAGE 2 -- All domains: walks visible [role=dialog],[role=alertdialog],.modal,[data-testid*=modal] elements. Clicks first matching close button: [aria-label*=close i],[aria-label*=dismiss i],[data-testid*=close i],button[class*=close]. Visibility filter: display!=none, visibility!=hidden, opacity!=0, size>10x10px.
  8. EXCLUSION (CRITICAL): overlays matching /accept.*cookie
  9. cookie.*consent
  10. privacy.*policy/i on AI quota hosts (chatgpt.com, gemini.google.com, claude.ai, copilot.microsoft.com, bing.com) are NEVER auto-dismissed. This is intentional per business strategy -- see cookie-consent-ai-strategy skill.
  11. INTEGRATION POINTS: hooked into WaitForEditorAsync (covers GPT + Gemini via WaitForChatGptEditorA11y and AskSession.FindEditorAsync) and WaitForClaudeEditorA11y. Runs once per ask call, 3s timeout, errors non-fatal.
  12. QA CHECK: wkappbot ask gpt 'say: hello' should complete without [POPUP:BLOCK] in logs. If popup persists blocking editor, check z-order -- banner may be behind editor (benign) vs covering it (bug). File suggest if blocking persists post-dismiss attempt.
