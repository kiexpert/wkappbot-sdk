wkjobs: AI process monitor

Shows all AI processes in the console session with CPU%, memory, state, and spawned child commands

user/developer

Steps

  1. PURPOSE: wkjobs.ps1 shows all AI processes (claude, codex, wkappbot, wkappbot-core, wkappbot-eye, wka11y) sharing the current console session with CPU%, memory, thread count, idle/busy state, CWD, and full command lines. A separate SPAWNED section shows non-AI child processes directly launched by those AI pids. AI_NAMES = claude, codex, wkappbot, wkappbot-core, wkappbot-core.new, wkappbot-eye, wka11y
  2. FLAGS: -Tree (hierarchy view) | -Watch (live refresh, Ctrl+C to exit) | -All (include processes from all sessions) | -RefreshSec N (Watch interval seconds, default 2) | -Kill (kill zombie helper processes -- safe ones only; prompts unless -Force) | -Leaks (print confirmed leaked zombie pids + kill cmd; exits 1 if found -- useful for CI/health check scripts) | -Force (skip confirmation in -Kill mode) | -ZombieMin N (idle minutes threshold for zombie classification, default 30)
  3. COLORS: claude=Cyan(idle)/Green(BUSY), codex=DarkYellow(idle)/Yellow(BUSY), wkappbot-core.new=DarkMagenta(idle)/Magenta(BUSY), wkappbot-core=DarkGray(idle)/Cyan(BUSY). BUSY=>20% CPU, active 1-20%, idle<1%. ZOMBIE HIGHLIGHT: idle process age>=ZombieMin (30m default) colored DarkRed with [old] label; safe-to-kill ones (wkappbot helper cmds: skill/suggest/ask/file/windows/logcat) colored Red with [ZOMBIE] label. PROTECTED (never colored zombie): wkappbot-core.*, wkchat, claude, codex, eye, chat, guardian, mcp
  4. SESSION MARKER: * prefix means process is in current console session. Without -All, only current session procs are shown
  5. SPAWNED SECTION: child processes of AI pids, conhost filtered. Columns: PPID (which AI spawned it), name, PID, CPU%, MEM, state, command line
  6. INTERNALS: Get-CimInstance Win32_Process for CommandLine+PPID, *** for CPU% snapshot, Get-Process for WorkingSet64+Threads+SessionId
  7. NOTE: loop variable is apid not pid -- PowerShell PID is a reserved automatic variable for current process ID, using it as a foreach var causes ReadOnly error
  8. WRAPPER: wkjobs.sh (bash) + wkjobs.cmd (CMD) are relative symlinks to wkwrap.sh in same dir. Run wkwrap.sh --install to add more. See also: wkappbot skill read wkwrap-ai-native-wrappers
  9. SOURCE: wkjobs.ps1 lives in WKAppBot/bin/wkjobs.ps1 (edit there). scripts/wkjobs.ps1 is a symlink (mode 120000). wkjobs.sh relay uses local wkwrap.sh copy so wkfind.sh keeps SDK-specific wkfind.ps1.
  10. PATH fix: prepend system dirs before codex exec to avoid PS shim shadowing system shell
  11. COLUMNS: PID, NAME, CPU%, MEM(MB), THR(threads), STATE, AGE, CWD (current working directory via NtQueryInformationProcess+ReadProcessMemory -- native kernel read, works even when PowerShell CWD differs), CMD (args only, exe path stripped). TERMINAL column: Get-TerminalHost walks parent chain skipping wkappbot*/conhost/claude/codex to find the terminal or IDE hosting the AI process (e.g. WindowsTerminal(12345) [tab title])
  12. MANUAL FALLBACK (when wkjobs hangs): Get-CimInstance Win32_Process | Where-Object { Name -match 'wkappbot|claude|codex|wkchat' } -- shows CommandLine per process. Zombie shell chains (powershell/cmd 30+ min old stuck helpers): use wkappbot taskkill --force <pids> or PowerShell process termination.
