LM Wiki — Personal Knowledge Base with Markdown (Claude Code + Obsidian)

Build a compound-interest knowledge base from any raw sources (web clips, YouTube transcripts, docs). No RAG, no embeddings, no vector DB. Claude Code processes raw/ into interlinked wiki/ pages. Based on Andrej Karpathy's LM Wiki approach: a markdown folder is enough.

Steps

  1. CORE CONCEPT — two folders only. raw/ = original sources (web clips, transcripts, docs, meeting notes) wiki/ = processed, interlinked markdown pages Claude writes Claude reads raw/, extracts entities/concepts/summaries, writes wiki/ pages with [[backlinks]]. Obsidian renders the link graph visually. Why not RAG? RAG = similarity search on chunks (find chunks similar to query). Wiki = relationship traversal (follow [[links]] through context). Wiki gives deeper context. Zero embedding cost. Zero vector DB. Karpathy: 'I thought I needed RAG. Just a markdown folder was enough.' 95% token reduction reported by early adopters vs full-context approaches.
  2. SETUP 1. Install Obsidian (free): obsidian.md → New vault → point to your wiki folder. 2. Get Karpathy's lm_wiki.md prompt from GitHub (search: karpathy lm_wiki). 3. Open Claude Code in your project folder. 4. Paste the full lm_wiki.md content then add: 'Read the above spec and implement this wiki system in the current folder.' 5. Claude Code creates: raw/ original sources go here wiki/ processed pages (concepts/, entities/, analysis/) .claude/ CLAUDE.md with workflow rules Claude reads every session wiki/index.md navigation map — AI reads this first to find relevant pages
  3. INGEST WORKFLOW — adding content to raw/ then processing Web content: Install Obsidian Web Clipper (Chrome Web Store). Settings → Default template → Location: set to raw/ Clips save to raw/ with tags + source URL automatically. YouTube transcript: Paste transcript text into raw/ as a .md file, then: 'ingest the new source in raw/' Any file: Drop .md / .txt / .pdf text into raw/, then ask Claude Code: 'ingest' or 'process new sources in raw/' After ingest: Claude creates wiki pages, links related concepts, updates wiki/index.md. Check Obsidian graph view to see new connections.
  4. QUERY — asking questions against your wiki Ask naturally in Claude Code or Claude.ai Projects: 'What is the most important thing about Claude Code?' 'Do I have any notes on MCP servers?' 'Summarize my content strategy notes' 'What did I capture last week?' Claude reads wiki/index.md first (navigation map), follows [[backlinks]] to relevant pages, synthesizes answer. No similarity search — pure link traversal, full context preserved.
  5. MAINTENANCE — keeping the wiki healthy Lint (health check): Type: 'lint' Claude scans wiki for broken links, orphan pages, missing backlinks, inconsistent data, gaps. Fixes or reports each issue. Run daily or weekly. Automate with Claude.ai Projects scheduled task. Hot cache (wiki/hot.md): ~500 chars of recent context cached here. AI reads hot.md first to orient without scanning the full wiki. Saves tokens significantly — especially on new sessions. Update: 'update hot cache with today's work'
  6. CLAUDE.AI PROJECTS — no-code ongoing management (alternative to Claude Code) 1. Claude.ai → New Project → select your wiki folder as project folder. 2. System prompt: 'Work in this wiki. Reference .claude/CLAUDE.md for workflow rules.' 3. First message: 'Scan the wiki and give me a status report.' Scheduled tasks (set up once, run automatically): Daily morning: briefing on recent additions + action items Weekly: lint run — fix broken links, fill gaps Auto-ingest: process any new files dropped in raw/ Index sync: keep wiki/index.md up to date Notion + Obsidian split (optional): Notion = operations, schedules, project status (database + automation features) Obsidian wiki = knowledge, strategy, research accumulation Both fed by Claude — different purposes, same AI backbone.
