wkchat session routing guard -- nested calls stay session-aware

wkchat starts an interactive chat session. When the current or parent process already carries a chat session marker, descendant wkappbot calls stay in session-aware routing mode so nested launches do not re-enter interactive chat.

user/developer
wkchatchatsessionlauncherroutingoperatorreference

Steps

  1. Chat sessions set and inherit WKAPPBOT_CHAT_SESSION=1
  2. Use wkappbot chat for interactive REPL only; nested commands inside the session must be treated as single-shot calls
  3. If a child launch needs interactive chat behavior, clear the session marker in the parent shell before starting it
  4. Verify the live behavior with wkappbot chat --help and wkappbot skill read wkchat-session-routing-guard
  5. Keep the outer chat guard in the launcher; nested chat sessions still inherit WKAPPBOT_CHAT_SESSION=1 for child routing
  6. When the session guard is active, Launcher keeps chat on the interactive stdio path and skips Eye routing
