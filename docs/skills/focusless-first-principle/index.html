포커스리스 우선 원칙

UIA Invoke/Value/Toggle/Select = 포커스 불필요. SendInput/Hotkey = EnsureFocus 필요. 포커스 탈취는 사용자 작업 방해 -- 항상 Focusless 먼저 시도.

Steps

  1. Focusless 가능: UIA Invoke, SetValue, Toggle, Select, Scroll
  2. Focus 필요: SendInput, Hotkey, WM_CHAR(일부), type --hotkey
  3. PostMessage(WM_CHAR) = Focusless로 키 입력 가능 (MFC 유용)
  4. CDP EvalAsync = 브라우저 내 JS 직접 실행 = Focusless
  5. 포커스 탈취 감지: FocusLaunchTracker -> runtime/focus_launch.json 기록
  6. WPF 오버레이: Spawn(showNoActivate:true) -> SW_SHOWNOACTIVATE(4), 포커스 탈취 없음
  7. [INVOKE-TIER-CHAIN] invoke/click fallback chain follows UIA accessibility standard. invoke Tier 0 FLUTTERVIEW WM_LBUTTON focusless, ~0ms invoke Tier 1 UIA InvokePattern focusless (fg restored if stolen) invoke Tier 2 BM_CLICK (Win32 button msg) focusless, no response detection invoke Tier 2.5 UIA pattern per ControlType focusless -- try BEFORE physical click: CheckBox / ToggleButton -> TogglePattern.Toggle() RadioButton / ListItem / TabItem / TreeItem / DataItem -> SelectionItemPattern.Select() ComboBox / MenuItem / TreeItem -> ExpandCollapsePattern.Expand() invoke Tier 3 A11yClick (physical SendInput) focus restored after click click Tier N-1 WS_EX_TRANSPARENT click-through -- covering windows made transparent temporarily click Tier N SendInput + focus restore click lands, focus returns to caller PRINCIPLE: if caller wanted focus they would have used 'a11y focus' first. Physical click is last resort -- only when no UIA pattern applies.
  8. [v6.2+ ELECTRON/MFC UIA SKIP] a11y find/inspect/windows/ocr skip UIA traversal for Electron (Chrome_WidgetWin_1 class AND non-Chromium proc like VS Code) and MFC/Afx windows (nkrunlite, Heroes4). Electron UIA traversal caused 30s DLL unload deadlock; MFC has no meaningful UIA tree anyway. Result: read-only a11y commands run 1-5s instead of 50s. Does NOT affect actual automation -- UIA still used when explicitly targeting an element. Only the discovery-phase batch traversal is skipped.
  9. [v6.8+ A11Y FOCUS TIER CHAIN] a11y focus = SmartSetWindowOrder + keyboard focus. SmartSetWindowOrder: child window (GetParent != null) -> BringWindowToTop (front of siblings, focusless); root window -> SetWindowPos behind-fg (Z-order rank 2, NOACTIVATE). A11yFocusElement full tier ladder: (-1) SmartSetWindowOrder on root ancestor, (0) CDP defA11yFocus() for Chrome, (1) UIA SetFocus, (2) Win32 SetFocus on element hwnd, (3) Win32 SetFocus on root hwnd fallback. NEVER SetForegroundWindow or SetActiveWindow -- zero keyboard-focus steal.
