wkappbot ask gpt zombie process -- 4-5 GB memory leak detection and fix

ask gpt --timeout Ns can hang as a zombie consuming 4-5 GB RAM. Detection and immediate kill procedure.

user/developer
wkappbotmemoryzombieaskgptleaktaskkillperformance

Steps

  1. SYMPTOM: system memory 80pct+. Get-Process sorted by WorkingSet64 shows wkappbot-core or wkappbot-core.new at 4000-5000 MB.
  2. IDENTIFY: Get-CimInstance Win32_Process -Filter Name LIKE wkappbot-core%
  3. Select ProcessId,WorkingSetSize,CommandLine. Look for CommandLine containing 'ask' 'gpt' '--timeout'. These are zombie pipeline health checks that hung.
  4. ROOT CAUSE: ask gpt fires with short --timeout (e.g. 3s) but the CDP/GPT pipeline hangs. Process keeps retrying internally and leaks memory over hours.
  5. KILL: C:/Windows/System32/taskkill.exe /F /PID <pid1> /PID <pid2>. User must authorize (per CLAUDE.md kill-protection rule).
  6. FREED: each zombie releases 4-5 GB. Two zombies = ~10 GB. System returns to normal immediately.
  7. PREVENTION: suggest to WKAppBot team -- add OOM watchdog that kills ask-gpt subprocesses if WorkingSet64 > 2 GB. File suggest with repro steps.
  8. SEEN: 2026-05-24, PIDs 23840 (4925 MB) and 32976 (4787 MB), both running ask gpt pipeline health check.
  9. FIX IMPLEMENTED (2026-05-24): AskCommands.Entry.cs -- replace proc.WaitForExit() with proc.WaitForExit((timeoutSec+60)*1000). If returns false: proc.Kill(entireProcessTree:true) + log [ASK] Hard-killed *-cli after Ns. Both AskClaudeCli and AskCodexCli patched. timeoutSec passed from dispatch at lines 896-897.
