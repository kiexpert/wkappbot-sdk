wkappbot ocr: screenshot-to-text, HTS owner-drawn, pipeline usage

wkappbot ocr runs OCR on a window or image file. Pairs with a11y screenshot for focusless MFC/HTS owner-drawn control text extraction. Covers language options, subprocess usage, coordinate output, pipeline patterns.

Steps

  1. BASIC USAGE: wkappbot ocr <window-title-or-image.png> [--lang kor+eng] [--save] [-o output.txt]. Runs OCR on a window screenshot OR image file. Prints all recognized text with coordinates. --save: saves annotated screenshot with bounding boxes. Example: wkappbot ocr nfrunlite -o holdings.txt
  2. PIPELINE -- screenshot then OCR (best for MFC/HTS): two-step: (1) wkappbot a11y screenshot GRAP -o snap.png (focusless, multi-node, cross-root). (2) wkappbot ocr snap.png [-o result.txt]. Separating capture and OCR lets you cache the screenshot, retry OCR with different lang, or preprocess the image.
  3. COMBINED ONE-LINER for owner-drawn controls: wkappbot ocr nfrunlite reads the active window directly. For specific panels: wkappbot a11y screenshot nfrunlite --form [2000] -o panel.png && wkappbot ocr panel.png. Handles MFC owner-drawn controls that have no UIA text properties.
  4. LANGUAGE OPTIONS: --lang kor+eng (default), --lang kor (Korean only), --lang eng (English only). HTS apps: use kor+eng for mixed stock codes (Latin) + Korean labels. The + separator means Tesseract reads both simultaneously, better for mixed-script screens.
  5. SUBPROCESS USAGE (Python): r = subprocess.run([WKBOT, 'ocr', snap_path, '-o', txt_path], capture_output=True, timeout=30); text = open(txt_path).read(). Or pipe directly: r = subprocess.run([WKBOT, 'ocr', snap_path], capture_output=True); text = r.stdout.decode(). No window focus needed for image-based OCR.
  6. HTS OWNER-DRAWN PATTERN: UIA read returns empty for MFC owner-drawn grids (nfrunlite [2000], [0338] etc). Solution: (1) wkappbot a11y screenshot nfrunlite --form [2000] -o grid.png (2) wkappbot ocr grid.png --lang kor+eng -o grid.txt (3) parse txt for stock codes and values. This is the correct 3-tier fallback: UIA -> a11y read -> screenshot+OCR.
  7. COORDINATE OUTPUT: OCR output includes per-word bounding box coordinates. Use these to identify which screen region contains specific values (e.g. profit/loss column). Useful for click targeting: find text position -> pass coords to a11y click --abs --x N --y N.
  8. WHEN TO USE OCR vs a11y read: prefer a11y read (fast, exact, no image processing). Use OCR when: (1) a11y read returns empty for owner-drawn controls, (2) text is rendered as image/bitmap, (3) need layout/position info, (4) MFC HTS panels with no UIA tree exposure.
