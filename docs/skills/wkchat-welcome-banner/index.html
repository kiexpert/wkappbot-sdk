wkchat welcome banner -- claude-code style boxed greeting on chat startup

Every `wkappbot chat` (interactive) prints a boxed welcome banner at session start: WKAppBot ASCII logo, version, current model, user/email (from license identity), Eye health (healthy/starting/down), and CWD. Width auto-adapts to console (clamped 60-120). Suppressed when stdin/stdout is redirected (piped, --help, scripted). Logo source-of-truth shared with UsageCommand via GetBannerLogoLines() so the help screen and chat banner never drift.

Steps

  1. [ENTRY] ChatCommand.cs Program.PrintWelcomeBanner() called once at session start. Idempotent via _welcomeBannerPrinted volatile flag -- chat has multiple branches (interactive claude, codex, AI REPL, OS shell) but banner prints only at the first one. try/catch wraps the core; banner is cosmetic so a failure NEVER breaks chat startup.
  2. [FIELDS RESOLVED] (1) ResolveVersionString -> v6.8.NN from assembly. (2) ResolveUserIdentity -> (login, email) from LicenseManager identity probe; falls back to Environment.UserName + ***. (3) ResolveDefaultModelName -> e.g. claude-sonnet-4-6 from settings. (4) ResolveEyeHealth -> healthy/starting/down via Eye tick probe. (5) TruncateCwd(Environment.CurrentDirectory, 60) -- long paths get ellipsis-truncated.
  3. [WIDTH] consoleW = SafeWindowWidth(); width = Math.Clamp(consoleW - 2, 60, 120); inner = width - 2. Banner box uses Unicode box-drawing chars (rounded corners ╭─╮ │ │ ╰─╯). Title segment ' WKAppBot v6.8.NN ' is centered in the top border. Greeting line: '안녕하세요 {greetName}님!'.
  4. [LOGO REUSE] GetBannerLogoLines() in UsageCommand.cs returns the 6 pre-padded ASCII art lines (the WKAPPBOT block-letter logo). Both the --help banner and the chat welcome banner pull from this single function. Refactored 2026-05-05 (commit 9b4cf3c3) to eliminate duplicated logo strings -- if the logo is ever updated, both surfaces follow automatically.
  5. [SUPPRESS WHEN PIPED] If Console.IsInputRedirected || Console.IsOutputRedirected -> skip banner entirely (returns without printing). Same gate is used by --no-autostart logic. This makes scripts and CI runs (`echo q | wkappbot chat`) silent and avoids polluting captured stdout with box-drawing chars.
  6. [SUPPRESS WHEN --help] When `wkappbot chat --help` is invoked, the help dispatcher returns before ChatCommand.Entry runs, so PrintWelcomeBanner is never reached. No special-case needed.
  7. [STARTUP CONTEXT] Banner prints AFTER PrintCallerHostBranding (Caller-Host: ... line) and AFTER EnsureChatAutoStartupRegistration silent registry probe, but BEFORE the first prompt. Order matters: license identity must already be resolved (Caller-Host probe loads it) so ResolveUserIdentity returns the real email.
  8. [AUDIT 2026-05-30] 3 empty FILE-MISSING refs in source_refs. Real refs would point to GetBannerLogoLines() in UsageCommand and ChatCommand banner emission. Needs next contribute pass.
