Browser-Side OCR via Tesseract.js CDP Injection (web ocr command)

Run OCR entirely inside a Chrome tab using Tesseract.js injected via CDP Runtime.evaluate. No screenshot roundtrip to server -- Chrome renders and recognizes in one step. Supports element-level and full-page OCR, parallel multi-selector, Korean+English default.

user/developer

Steps

  1. Usage: wkappbot web ocr <grap> [--selector <css>] [--lang eng+kor]. grap identifies the Chrome tab. --selector targets a specific DOM element; omit for full page. --lang sets Tesseract language codes (default: eng+kor). Prints recognized text to stdout.
  2. How it works: (1) CdpTesseract.EnsureLoadedAsync injects Tesseract.js from CDN (cdn.jsdelivr.net/npm/tesseract.js@5) via script tag if window.__wkTesseractReady sentinel absent. (2) Page.captureScreenshot with clip rect for element bbox (DPR-aware), or full viewport. (3) base64 PNG passed to Tesseract.recognize() in-browser. (4) result.data.text returned via Runtime.evaluate. Tesseract.js cached in tab after first load -- subsequent calls skip CDN fetch.
  3. Parallel OCR: pass multiple --selector values or run Promise.all in JS. Browser handles concurrency natively. Example: wkappbot web run <grap> "Promise.all([querySelector('.a'), querySelector('.b')].map(el => Tesseract.recognize(el)))". Faster than sequential server-side OCR for multi-region tasks.
  4. Canvas / WebGL OCR: use canvas.toDataURL('image/png') to get base64, then Tesseract.recognize(base64). Works on game UIs, chart libraries, any GPU-rendered content that would be black/blank in a screenshot from outside Chrome. Key advantage over wkappbot OCR command which captures the Win32 screen.
  5. Limitations: (1) CDN required on first load per tab -- offline fallback NYI. (2) Background tab throttling may affect dynamic content accuracy. (3) Tesseract.js WASM loads ~10MB on first use. (4) For static text on native Win32 UI (not browser), use wkappbot a11y read or wkappbot ocr instead.
