Part of: claude-md-harness-rules

Steps

  1. EXAMPLES: ## harness:safe CLAUDE\.md (allow Edit on CLAUDE.md). ## harness:block (?i)● Bash\(.*rm -rf (block). ## harness:warn (?i)● Bash\(.*sed -i (warn). ## harness:done (?i)completed.
  2. BODY LINES: Plain text = shown as help. Line starting with ! = PowerShell command, output inserted. Example: !wkappbot skill read wk-ai-tools (shows skill content in block message).
  3. TEMPLATE: no harness: sections in CLAUDE.md -> ~/.claude/harness-template.md auto-appended. Default: safe CLAUDE.md, warn wkedit--line, block bash-pwsh, done skipped.
  4. BEST PRACTICES: Use safe before block to whitelist exceptions. Anchor to '● Bash\(' or '● Edit\(' to avoid matching tool args. Keep regex simple (no lookahead). Test: wkharness -Test.
  5. harness:skill FULL USAGE: ## harness:skill csharp.*MyCdpContext then 3 'wkappbot skill read <id>' lines. IDs must exist in catalog and be distinct. Catch-all (condition B) blocks unregistered source files and prints exact section to add. skill-update LOCK (code_changed.lock) separate: cleared by any skill edit/contribute, gates next delegation.
