a11y playbook writing

Create and revise executable WKAppBot playbooks/scenarios for focusless desktop automation. Use when drafting or updating YAML scenarios, Notepad-style demos, save-dialog recovery flows, or any target-heavy automation that should prefer `a11y find`, paste-ready grap targets, UTF-8-safe files, and graceful close behavior over brittle clicks or taskkill.

Steps

  1. Read the shared repo guidance first: AGENTS.md, CLAUDE.md, and README.md. Keep any new prose English-first and UTF-8 encoded; only UI-localized labels may stay localized when the target app requires them.
  2. Reuse existing skills before inventing new flow: `wkappbot skill list`, then `wkappbot skill read a11y-find`, `grap-target`, and `control-ui-without-stealing-focus-3-tier-focusless-strategy`.
  3. Write the playbook as a runnable scenario: `scenario`, `config`, `app`, `steps`, optional `teardown`. Prefer `prefer_focusless: true` and `focus_check: false` when the goal is background automation.
  4. Discover exact targets with `a11y find` and copy the emitted `# TARGET` grap. Prefer node-tag / grap-path resolution over raw `name` matching for buttons and modal controls.
  5. For Notepad close flows, prefer `window_close` first. If a save prompt appears, dismiss it by invoking the button found through the a11y node tag path. Keep `press_key` only as fallback, not as the primary path.
  6. Avoid destructive process-kill shortcuts for Notepad. Use graceful close, prompt dismissal, and only narrow fallback logic when the UI path fails.
  7. Prefer stable selectors in scenarios: `control_type`, `automation_id`, and `description` over fragile visible text. Use localized text only where the OS/app label itself is localized.
  8. Validate the playbook after edits with the official binary on PATH: `wkappbot validate <file>` and, when relevant, `wkappbot run <file>`. If validation fails with log or lock issues, inspect runtime state before assuming the YAML is wrong.
  9. After creating or updating the skill, verify it with `wkappbot skill read <id>` and keep the skill body short, imperative, and reusable.
  10. Use wkappbot skill contribute / wkappbot skill edit for all skill changes; never hand-edit .skill.json files.
