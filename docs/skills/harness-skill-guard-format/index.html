harness:skill Format — Required Single-Line Pattern

Documents the mandatory format for harness:skill rules in CLAUDE.md. Pattern must use 3 required skills on single lines with inline # comments (shell-safe).

user/developer

Steps

  1. MANDATORY FORMAT (single-line only): ## harness:skill <file-glob-pattern> followed by 3 skill read commands, each on its own line with trailing # comment. Shell ignores # and beyond, so multi-line comments break harness parsing.
  2. REQUIRED SKILLS (3-role pattern): Usage (how code is used — policy/scope/rules), Impl (how code is implemented — algorithms/validation/errors), Task (what to do when editing — keywords/tests/side-effects).
  3. CORRECT EXAMPLE: ## harness:skill csharp.**/MyCdpContext.cs followed by three lines: 'wkappbot skill read standard-appbot-window # Usage: caller detection', 'wkappbot skill read standard-chrome-window # Impl: window filtering', 'wkappbot skill read wkfind-caller-hwnd-validation-3tier-pattern # Task: ancestor walk maintenance'
  4. SHELL-SAFE FORMAT: # comments at end of line are ignored by shell. Never break into multiple lines (harness parser expects single-line entries). Trailing # lets humans document WITHOUT breaking machine parsing.
  5. SKILL ID VALIDATION: Each of the 3 skill IDs is auto-validated by wkappbot skill edit. If any skill does not exist, the edit is rejected with missing IDs listed. Always verify skill IDs exist before submitting.
  6. AVOID (FORBIDDEN): Multi-line comments with opening ## or /*, multi-skill-read on same line, embedding harness:skill text inside tool steps (looks like rule but won't parse), using or/and to group skills
