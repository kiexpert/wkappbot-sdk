wkedit shell distortion recovery

3rd retry in wkedit.sh: recover original args from parent cmdline when shell distortion causes old_string not found

user/developer

Steps

  1. CONCEPT: 3rd retry after 2-level auto-retry (--replace-all + --old-file). When shell pipe layers distort backslashes/quotes/regex before reaching wkappbot, recover original cmdline from parent process.
  2. WHEN-NEEDED: bash -c distortion, pipe escaping, MSYS2 path conversion. Symptoms: --regex fails with correct pattern; literal match fails despite visible text. Gap after existing 2 retries.
  3. STEP 1 detect parent shell: check /proc/$PPID/cmdline (Linux procfs). If absent (MSYS2/git-bash on Windows typically lacks it), fall back to WMI: powershell.exe -NoProfile -Command "(Get-CimInstance Win32_Process -Filter 'ProcessId=$PPID').CommandLine"
  4. STEP 2 extract original args: parse CommandLine for bash -c argument. Use python3 shlex.split() to recover token list. Find wkappbot/file/edit tokens, extract positional old/new string args.
  5. STEP 3 compare+retry: if recovered_old != received_old -> distortion confirmed. Write recovered_old to tmpfile, retry with --old-file tmpfile.
  6. CONSTRAINTS: (a) MSYS2 git-bash lacks /proc -> WMI only path on Windows. (b) WMI ~200ms overhead. (c) Eye/MCP pipe path: PPID=wkappbot-core.exe not bash -> inapplicable. (d) python3 shlex may not perfectly reconstruct all quoting styles. (e) Only useful for interactive terminal callers, not Eye.
  7. IMPLEMENTATION SKETCH: _distortion_recover() added in wkedit.sh after existing _do_edit() 2nd retry. Calls WMI or /proc, runs python3 inline to parse shlex, diffs recovered vs received, retries with --old-file if different.
  8. STATUS: DRAFT. Not implemented. Requires WMI reliability testing on MSYS2+Windows 11 before proceeding. Test script: wkedit_test_distortion.sh
