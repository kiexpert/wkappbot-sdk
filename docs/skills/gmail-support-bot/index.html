  3. Auto-reply routing: (1) activation/license -> GH API perm + expiry lookup; (2) refund -> 7-day policy; (3) renewal -> payment info; (4) feature/usage -> docs; (5) fallback -> human handoff.

  5. Refresh token expiry: if unused 6+ months or revoked, re-run OAuth flow in Python, capture localhost:8765 callback code, exchange for new GMAIL_REFRESH_TOKEN, update .env.
  6. Auth scopes: gmail.modify (read + send + label, no delete). Redirect URI: http://localhost:8765.
  7. OAUTH SETUP LESSONS (salpil 2026-05-01): (1) wkappbot web open fails with lockfile -- Chrome already on port 9222 not 9223. Use CDP port 9222 with suppress_origin=True via Python websocket. (2) Chrome hwnd visible window is NOT hwnd:0x5C14E2 (zero-size bg window) -- find visible Chrome via Win32 EnumWindows+GetWindowRect pid filter. (3) DOM click and mouse_event at viewport coords fail on Google consent page -- use wkappbot a11y invoke instead: wkappbot a11y invoke {hwnd:CHROME_HWND,domain:accounts.google.com}#Doc_RootWebArea//*Allow*. CORRECT approach. (4) Auth code expires instantly if token exchange fails (e.g. cp949 UnicodeDecodeError) -- always decode response as utf-8. Need fresh code on exchange failure. (5) Consent page tab URL contains signin/oauth/consent (not accountchooser). (6) After a11y invoke Allow, check Chrome CDP tabs for localhost:8765 URL and extract code param. Summary: use wkappbot a11y invoke, not raw Python mouse clicks.
