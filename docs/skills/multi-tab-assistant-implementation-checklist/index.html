Multi-tab assistant implementation checklist

Execution checklist for porting a multi-tab assistant interface into AppBot, focused on adapters, event schema, isolated sessions, permissions, and resume behavior rather than cloning a specific host UI.

Steps

  1. Freeze the porting scope before coding: keep the work to AppBot integration, orchestration, and session isolation.
  2. Define the adapter contract first: stream, cancel, retry, health-check, and usage-estimate methods.
  3. Implement one canonical event bus for user_message, assistant_delta, assistant_done, tool_call, tool_result, error, and status events.
  4. Store tab state by workspace, provider, and thread id so Claude, Codex, and Copilot never share live context.
  5. Build the renderer around streaming, buffering, cancel, retry, and regenerate actions that map to the adapter contract.
  6. Add explicit context injection for active folder, selected files, cwd, and recent commands with user-visible toggles.
  7. Put shell and file actions behind a permission gateway and keep progress visible in the timeline.
  8. Surface provider timeout, auth failure, rate limit, offline mode, and degraded fallback as explicit states.
  9. Add token estimate preflight, soft warning threshold, hard-stop threshold, and per-session usage summary.
  10. Persist compact session snapshots and restore tabs on restart without replaying hidden state.
  11. Add integration tests for stream ordering, tab isolation, cancellation race, permission denial, and restore correctness.
  12. Ship in milestones: skeleton, adapters, permissions and persistence, then polish and observability.
