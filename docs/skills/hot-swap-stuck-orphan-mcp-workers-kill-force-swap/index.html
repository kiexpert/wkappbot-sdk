Hot-Swap Operator Cheatsheet (--force-swap + manual + 3-layer architecture)

Hot-swap operator reference. Covers force-swap (wkappbot --sudo --force-swap), manual orphan-kill + restage for stuck builds, and a 3-layer architecture recap (Eye FSW rename | Admin Eye self-respawn | MCP Launcher swap). Use when hot-swap misbehaves or when reasoning about which layer is responsible for a symptom.

Steps

  1. Force-swap one-shot: wkappbot --sudo --force-swap eye tick (or any command). What it does: UAC elevates → TryAdminHotSwap(force=true): - Skips 60s lag guard (--force bypasses the mtime delta check) - Reads Eye PID from runtime/eye_ticks.jsonl (last 'Tag':'eye' entry) - Kills orphan wkappbot-core pids (spares Eye, WhisperRing, wkchat sessions, self) - Renames live wkappbot-core.exe → .old-<ts>.exe - Copies wkappbot-core.new.exe → canonical wkappbot-core.exe - Eye + WhisperRing are also terminated (with --force flag) so they respawn from fresh exe - Watchdog VBS revives Eye within ~2min (2min chat blind window) When to use: normal auto-swap stale for 1h+ AND admin Eye itself running old code AND 2min blackout acceptable. Without --force: same flow but 60s lag guard active and Eye/WhisperRing preserved.
  2. Use --force-swap when: normal auto-swap sat on stale live-exe for an hour+ AND admin Eye itself is running old code AND a 2min Eye blackout is acceptable
  3. Verify after --force-swap: ls -la bin/wkappbot-core.exe shows fresh mtime + wkappbot eye tick shows fresh pid and new behavior
  4. Manual path symptom: wkappbot hotswap prints step1 rename to .old failed because another process holds the file lock
  5. Manual diagnosis: powershell.exe -Command Get-Process wkappbot-core -ErrorAction SilentlyContinue shows multiple pids holding the exe; blank Path column = admin-protected orphan
  6. Manual Eye pid find: wkappbot a11y windows locates the WK AppBot Eye pid and the WhisperRing pid; memo these -- never kill them manually
  7. Manual orphan identification: any wkappbot-core pid that is NOT Eye and NOT WhisperRing is an orphan candidate; a11y find with pid filter confirms role
  8. Manual kill: powershell.exe -Command Stop-Process -Id PID1,PID2 -Force (admin-protected orphans require admin shell)
  9. Manual restage and swap: cp D:/SDK/bin/wkappbot-core.exe D:/SDK/bin/wkappbot-core.new.exe then wkappbot hotswap
  10. Manual success check: a11y windows shows Eye proc name as wkappbot-core (not .old-...) and memory drops from 2400MB to 800MB
  11. Orphan workers come from Eye restart loops; if StartTime is before Eye's current boot time they are confirmed orphans
  12. Why --force-swap exists: 2026-04-19 session hit admin orphans 51232/53024 pinning v5.x exe for 8h+; manual mv rename-then-copy worked but Eye stayed on v5.x admin; --force-swap bundles the full recycle so future sessions do not need manual surgery
  13. Architecture Layer 1 - Eye rename-swap (AppBotEyeGlobalMode.cs TryRenameSwap): happy-path FSW on .new.exe arrival renames canonical exe to .old-ts then copies .new.exe to canonical. Gentle startup swap if .new.exe already exists at Eye boot. Admin-busy defer via ElevatedEyeServer.IsBusy. Same-mtime retry skipped via _lastFailedSwapStamp
  14. Architecture Layer 2 - Admin Eye self-respawn (AppBotEyeCommands.cs isElevatedArg): elevated Eye spawns successor with its own admin token -- no UAC. Dual FSW: .new.exe arrival (early drain) + .exe swap (fast path). drainTriggered flag prevents double-spawn. Startup with .new.exe present triggers immediate drain
  15. Architecture Layer 3 - MCP Launcher swap (McpProxy.cs HOT-SWAP): FSW on canonical exe path change (AFTER Eye rename). Launcher owns Core pipe lifecycle not the exe file. 6 steps: track inflight requests -> detach stdin -> spawn new Core -> replay initialize+tools/list -> stdout relay -> drain old Core 60s. Admin-first: if admin alive defer swap until admin exits
  16. Layer separation rule: Eye moves files. Launcher replaces Core pipe. MCP server (embedded in Eye) ships with Eye -- no separate hot-swap needed
  17. Full gentle-swap flow: publish -> .new.exe staged -> Eye rename -> Admin Eye self-respawn -> Launcher Core swap. Each layer has independent fail-stamp skip so a single flaky layer does not block others permanently
