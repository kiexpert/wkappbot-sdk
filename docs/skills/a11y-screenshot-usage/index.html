a11y screenshot: focusless capture, multi-node, cross-root, subprocess

wkappbot a11y screenshot is fully focusless -- never steals keyboard focus or changes z-order. Supports multi-node composite, cross-root windows, UIA scope crop, MDI form mode, subprocess usage. Use this instead of any manual PrintWindow/mss/click approach.

Steps

  1. BASIC USAGE: wkappbot a11y screenshot GRAP [-o output.png]. Focusless -- NO click, NO SetForegroundWindow, NO z-order change. Just pass the window grap. Output last stdout line: SAVED:PATH. Example: wkappbot a11y screenshot nfrunlite -o snap.png
  2. FOCUSLESS GUARANTEE: screenshot NEVER steals keyboard focus or changes window z-order. Safe during live trading, real-time feeds, any latency-sensitive context. If your code calls SetForegroundWindow or a11y click before capturing -- REMOVE IT. wkappbot handles occlusion internally via PrintWindow PW_RENDERFULLCONTENT.
  3. MULTI-NODE MODE: pass 2+ grap args OR single grap with UIA #scope. Captures each target independently, composites to union bounding box, masks pixels outside any target rect to alpha=0. Cross-root windows work -- targets from different process trees composited correctly. Example: wkappbot a11y screenshot TAB_GRAP GRID_GRAP -o combined.png
  4. SINGLE vs MULTI: Single grap no scope -> full-window capture (fastest). Single grap + #scope (UIA element) -> crops to that element. Two or more graps -> union composite of all targets. Use multi-node for extracting panels from complex MFC HTS trading apps.
  5. SUBPROCESS USAGE (Python): r = subprocess.run([WKBOT, 'a11y', 'screenshot', grap, '--out', path], capture_output=True, timeout=15); success = r.returncode == 0. NEVER add SetForegroundWindow or click before this -- defeats focusless design. Parse output path from last stdout line: SAVED:PATH.
  6. FORM MODE for MDI apps: wkappbot a11y screenshot GRAP --form FORM_ID -- captures a specific MDI child form e.g. nfrunlite [2000] holdings panel. Brings MDI child to front WITHIN the parent app without stealing OS-level keyboard focus.
  7. OCCLUSION HANDLING: PrintWindow PW_RENDERFULLCONTENT renders the window even when partially or fully occluded -- no need to bring it to front. GPU/DirectX windows fall back to screen-coordinate capture; ensure window is visible on screen. Still NO click or focus steal.
  8. REAL-WORLD PATTERNS: (1) HTS holdings: wkappbot a11y screenshot nfrunlite --form [2000] -o holdings.png. (2) Multi-panel: wkappbot a11y screenshot TAB_HWND_GRAP GRID_HWND_GRAP -o panel.png. (3) Stdout: wkappbot a11y screenshot GRAP --stdout. (4) UIA crop: wkappbot a11y screenshot App#DataGrid -o grid.png. (5) Cross-root: works automatically -- just list all hwnd graps.
  9. MULTI-TARGET GRAP SYNTAX (key feature): list any number of grap expressions separated by spaces. Each grap can point to a DIFFERENT process, window, or UIA element. wkappbot resolves each independently and composites the result. No setup needed -- just enumerate what you want. Example: wkappbot a11y screenshot nfrunlite#TabCtrl nfrunlite#GridCtrl SomeOtherApp -o all.png. The union bounding box of ALL targets becomes the output canvas; areas not covered by any target are masked transparent. This is the ONLY tool that does cross-root focusless multi-window capture in one call.
