wkfind quick: Process-chain caller window detection patterns

Quick reference for finding and fixing caller HWND issues. When you suspect wrong window detection, use this checklist.

user/developer
quick-refcallerHWNDprocess-chainwindow-detectionlauncher

Steps

  1. 1. Spot the symptom: Chrome window placement wrong, HWND validation rejects unexpectedly, JSON output shows wrong fg/fgT, or caller position is off-screen.
  2. 2. Check detection source: Launcher/Program.cs Main(), lines 234-258. Look for GetParentProcessId loop that walks parent chain.
  3. 3. Check forwarding path: Launcher line 1030 (BuildDetachedEnvBlock) adds WKAPPBOT_CALLER_HWND to env. Verify it's not stripped by forwardArgs.Where().
  4. 4. Check usage in Core: Search Core repo for 'WKAPPBOT_CALLER_HWND' and 'ComputePlacementNearCaller'. That's where the value is used.
  5. 5. Verify persistence: After running a cdp command, check wkappbot.hq/cdp-state.jsonl for 'caller_hwnd' and rejection reasons.
  6. 6. Test the fix: Build Launcher, hot-swap, run wkappbot a11y find '*' from different terminals/apps, capture LAUNCH JSON, verify fg matches caller not foreground app.
