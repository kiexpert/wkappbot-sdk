wkdoctor: SDK environment health check

flutter-doctor-style health check for wkappbot-sdk environment

user/developer

Steps

  1. USAGE: wkdoctor [-Json] -- flutter-doctor style [+]/[x]/[!] output, exit 1 on failures
  2. LOCATION: bin/wkdoctor.ps1 + bin/wkdoctor.cmd in SDK repo
  3. CHECKS (10): wkappbot.exe presence+version, wkappbot-core.exe, a11y.exe (warn), Eye tick ctx%, dotnet 8 SDK, skills catalog count, nightly-guard in ~/.claude/settings.json, bin/ in PATH, .wkappbot/config.json, wkappbot.hq/ dir
  4. FLAGS: -Json for machine-readable output (ConvertTo-Json), exit 0=all pass, exit 1=any fail
  5. RUN: wkdoctor OR wkdoctor -Json (pipe to ConvertFrom-Json for parsed output)
  6. SETUP CHECK: run after fresh clone + setup.ps1 to verify environment is healthy
  7. ROBUSTNESS: all checks use file/process/PE-version APIs only -- zero wkappbot subprocess calls (avoids Eye IPC stall in subprocess context)
  8. ARCHITECTURE: wkdoctor.ps1 is a thin orchestrator; check logic lives in bin/wkappbot.hq/doctor/*.ps1 plugins (01-binaries, 02-runtime, 03-skills, 04-config, 05-hq). Each module calls Add-Check/Emit from orchestrator scope. No wkappbot subprocess calls -- uses PE VersionInfo + Get-Process + file count for robustness in any execution context.
  9. PLUGIN STATUS: 5 modules written (01-binaries, 02-runtime, 03-skills, 04-config, 05-hq). Orchestrator rewritten as thin dot-source loader. All wkappbot subprocess calls removed. Opus healing review pending.
  10. 10. CODEX SYMLINK CHECK (50-codex-symlink.ps1): auto-detects and repairs broken VS Code extension codex.exe symlinks. Checks three candidate paths: D:/GitHub/WKAppBot/bin/codex.exe, D:/GitHub/wkappbot-sdk/bin/codex, D:/GitHub/wkappbot-sdk/bin/codex.exe. If symlink target is missing, auto-repairs by finding latest openai.chatgpt-* extension in ~/.vscode/extensions or falling back to ~/.codex/.sandbox-bin/codex.exe. Reports [+] ok (real file or valid symlink), [!] warn (missing file), [x] fail (broken symlink with no repair source).
