Black desktop: Progman stuck on wrong monitor after topology change

Win11 multi-monitor race: Progman anchors to secondary monitor after connect/disconnect, leaving primary monitor showing DWM fallback color. Fix: restart explorer.exe (2-3s blip).

user/developer
blackdesktopprogmanworkerwmulti-monitorexplorerwallpaperspotlight

Steps

  1. SYMPTOM: Primary monitor shows solid black/dark. Apps render normally. Icons missing. GetPixel(0,0) returns HKCU Colors Background value (default black #000000).
  2. ROOT CAUSE: Win11 Spotlight + multi-monitor topology change race. DesktopSpotlight.dll fails WM_SPAWN_WORKER for all monitors. Progman anchors to secondary only. DWM fallback fills primary.
  3. DIAGNOSE: FindWindow('Progman') hwnd rect covers secondary monitor only. HKCU\Control Panel\Colors\Background = '0 0 0'.
  4. FIX: Stop-Process -Name explorer -Force; Start-Sleep -Milliseconds 1500; Start-Process explorer. 2-3s blip then auto-recover.
  5. VERIFY: GetPixel(screen DC, 0, 0) returns warm wallpaper color. Icons visible again.
  6. DO NOT call SPI_SETDESKWALLPAPER before fixing Progman -- it re-anchors Progman to wrong monitor.
  7. OPTIONAL persistent fix: Set-ItemProperty HKCU:\Control Panel\Colors Background '255 255 255' so future races show white not black.
  8. 2026-05-20 POST-MORTEM: Pass 2 of screensaver close also wiped ChatGPT Chrome and Edge windows because SampleWindowAvgBrightness(PrintWindow) returns avgY=0 for hardware-accelerated windows (Chrome/ANGLE/DirectX). These passed the black-fullscreen test despite being real app windows. Fix needed: add known-app exclusion list to Pass 2/4/5 (chrome, msedge, consent, firefox, etc.) in addition to explorer.exe guard.
