ScenarioRunner: process: key + --no-dup flag for existing process adoption

Adopt a running process instead of launching when process: YAML key is set or --no-dup CLI flag is used. Avoids duplicate launches for elevated HTS processes.

user/developer

Steps

  1. Use process: <exeName> in scenario YAML app block to adopt-only (fail if not running). Use app.adopt: true for soft-adopt (try adopt, launch if absent). Use --no-dup CLI flag to adopt by launch exe name if already running. TryAdoptProcess uses Process.GetProcessesByName(exeName). Elevated processes (like nkrunlite/nfrunlite) are adopted and then the admin Eye proxy is used. Evidence: [RUN] Adopted existing process: nfrunlite (pid=8420)
  2. In scenario YAML: set app.process: nfrunlite to adopt-only. If process not found, scenario fails immediately (no launch fallback).
  3. Use app.adopt: true for soft-adopt: tries GetProcessesByName on Launch exe first, launches fresh only if not found.
  4. CLI: wkappbot run <scenario.yaml> --no-dup skips launch if exe already running (NoDup=true in ScenarioRunner). Elevated processes use admin Eye proxy automatically after adoption.
