Codex-Friendly Skill Template

A reusable template for writing wkappbot skills that are useful to both Claude and Codex. Use short, orthogonal options only when they improve safety, verification, or debugging.

developer
skilltemplatecodexclaudeoperatorverifydry-runreview

Steps

  1. Write the skill in English only and keep the steps short, executable, and testable.
  2. State the primary job in one sentence: what task the skill helps the agent do.
  3. Classify the skill first using the Skill Audience Taxonomy: operator, developer, project, or user.
  4. Add only the minimal operator options that actually help execution: verify, audit, dry-run, review, inspect, list, export, import, or install.
  5. Prefer safety and reproducibility over cleverness: every option should reduce ambiguity, not increase it.
  6. Include one explicit verification step whenever the skill changes state or affects output.
  7. If the skill affects target selection or automation, state the output contract first and the search/execute flow second.
  8. If both Claude and Codex will use the skill, write the steps so they work for either one without tool-specific jargon unless it is necessary.
  9. HARD LIMITS (Codex skips silently on violation): ID <= 64 chars, Description <= 1024 chars. Verify before contribute: echo -n 'id' | wc -c. Budget 58 chars in base slug if 3-tier split planned (-howto suffix = +6).
