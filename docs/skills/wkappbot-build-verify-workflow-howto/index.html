WKAppBot Build Verify Workflow T2 HowTo

T2 domain tier. Refactor loop, partial-class pattern, common errors, smoke check commands.

user/developer
Part of: wkappbot-build-verify-workflow

Steps

  1. Refactor loop: (1) make change (2) wkappbot-pub\build.cmd (3) check last 3 lines for staged+skills installed (4) wkappbot --version to force swap (5) wkappbot <affected-cmd> smoke test (6) git add+commit ONLY after all green.
  2. Partial-class split pattern: new file must have same namespace WKAppBot.CLI AND internal partial class Program. No extra using-statements beyond what extracted code needs.
  3. CS0246 (type/namespace not found): new file created but not referenced, OR extracted method left dangling reference. Read error location and verify both sites.
  4. Smoke check: wkappbot --version (expect base version). wkappbot exec list (expect built-in presets). wkappbot <affected-command> with minimal args.
  5. Launcher auto-swap failing: see hot-swap-stuck-orphan-mcp-workers-kill-force-swap skill. Short: wkappbot --sudo --force-swap eye tick when admin orphan blocks.
  6. After deploy: wkappbot skill sync to push local edits to HQ. Conflicts -> wkappbot skill sync --resolve <id>. Never leave split-brain pending.
