a11y find - output format and process resolution

How wkappbot a11y find resolves windows and process trees, and how to keep its output aligned with the current # FOCUS / # TARGET / # INFO contract. Useful when Claude or Codex is changing find behavior or debugging target ambiguity: proc is the identity, hwnd is the disambiguator, and root hwnd is only a search entry point. Include short operator flags only when they help verification or debugging.

Steps

  1. Keep the emitted output aligned with the current contract: one shared # FOCUS line, one # TARGET block per match, and optional indented # INFO lines.
  2. Treat the grap as what was actually matched: proc/domain/cmd/title/cls/file are matchable fields; hwnd is for disambiguation, not identity.
  3. Separate root hwnd from process-owned hwnd; when a process has no own window, resolve its effective host window through the parent chain.
  4. Keep output shell-safe and markdown-friendly: quote the full grap expression, avoid extra noise, and preserve paste-ready tokens.
  5. Prefer short operator flags like verify, review, and dry-run when they make the workflow safer or easier to audit.
  6. Verify by rerunning a11y find on the emitted hwnd:0x... token and checking [OK].
  7. Prefer process-first search logic for matching, but preserve focus context whenever interaction side effects could matter.
