MCP Admin Core Swap: Elevation-Triggered Graceful Cutover

How MCP Launcher spawns an elevated admin Core on demand and cuts over transparently, with hot-swap deferral while admin is active.

user/developer
mcpadminelevationswapuaclaunchernamed-pipeproject

Steps

  1. ## 트리거 조건
  2. normal Core가 UIPI 차단 감지 -> 응답에 '_elevationRequired:true' 포함 -> Launcher stdout relay가 가로챔 (suppress, client에 미전달)
  3. ## 어드민 Core 스폰 (SpawnAdminCore 백그라운드 스레드)
  4. 1. NamedPipe 서버 2개 생성: wkappbot-mcp-admin-{PID}-stdin / -stdout (Launcher가 서버, admin Core가 클라이언트)
  5. 2. ShellExecuteExW runas -> wkappbot-core.exe mcp --admin-pipes {stdin} {stdout} (UAC 팝업)
  6. 3. 60초 WaitForConnectionAsync -- UAC 승인 후 admin Core가 접속
  7. ## 절체 (transition) 순서
  8. 1. 기존 normal Core stdin close (CloseHandle) -> EOF -> drain mode 진입
  9. 2. adminMode = true -> 이후 stdin은 모두 admin Core로 라우팅
  10. 3. initialize 리플레이 -> 원래 elevation 요청 재전송 -> admin Core가 처리
  11. 4. admin Core stdout relay: 응답 id로 inflight 제거 -> client에 포워딩
  12. ## hot-swap과의 상호작용
  13. FSW가 .new.exe 감지해도 adminMode=true면 -> pendingSwapWhileAdmin=true로 defer (normal Core swap 대기)
  14. admin Core stdout EOF (= admin Core 종료) -> finally에서 activeStdinWriter=null + pendingSwapWhileAdmin 로그
  15. pending swap은 Launcher가 다음 FSW 이벤트(새 stamp) 때 재처리 -- 자동으로 normal Core가 새 버전으로 교체됨
  16. ## 실패 시
  17. UAC 거부 -> elevationRequestLine에서 id 추출 -> JSON-RPC error -32001 'Elevation denied by user' 반환
  18. 60s 타임아웃 -> TerminateProcess(adminProc) + pipe 정리
  19. ## 핵심 설계
  20. normal Core + admin Core 동시 공존 불가 -- 절체 시 normal Core는 drain 후 종료
  21. admin Core가 살아있는 동안 hot-swap은 defer -- 버전 불일치 방지
