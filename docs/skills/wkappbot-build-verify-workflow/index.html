WKAppBot build + verify workflow (for AI code agents)

How to build and verify WKAppBot after code changes. Required reading for Codex / Haiku / any AI CLI delegated to refactor or edit wkappbot source. Covers the single publish command, green-build signature, hot-swap staging output, and failure diagnosis.

Steps

  1. Single build command (Release mode, all projects): C:/Program Files/dotnet/dotnet publish D:/GitHub/WKAppBot/csharp/src/WKAppBot.CLI/WKAppBot.CLI.csproj -c Release --verbosity minimal
  2. Working directory: anywhere, but D:/GitHub/WKAppBot is canonical. Must use the quoted Program Files path on Windows; plain dotnet may hit an older SDK
  3. Green-build signature (last 3 lines of output): wkappbot-core.new.exe staged for hot-swap AND skills installed to HQ. Exit code 0. Presence of warning CS8604 or similar nullable warnings is fine -- only CS-prefixed errors block
  4. Typical red-build signatures: error CS0xxx (compile error), error MSB (msbuild error), FileNotFoundException on copy. Show the error line; do not retry blindly
  5. Timeout budget: 180-300 seconds on warm build (incremental), up to 420 seconds on cold. Use timeout 300000 ms when calling via Bash tool
  6. After successful build the canonical wkappbot-core.exe is NOT yet updated. The launcher rename-swap happens on next wkappbot invocation (hot-swap layer 3). Running wkappbot --version triggers the swap
  7. Launcher auto-swap failing? See hot-swap operator cheatsheet (hot-swap-stuck-orphan-mcp-workers-kill-force-swap). Short answer: wkappbot --sudo --force-swap eye tick when admin orphan blocks
  8. For a quick smoke check post-build: wkappbot --version should print the expected base version (currently 6.0.x). wkappbot exec list should list built-in presets including codex notepad calc
  9. Refactor verification loop: 1. make change 2. dotnet publish 3. check last 3 lines for staged + skills installed 4. wkappbot --version to force swap 5. wkappbot <affected-command> smoke test 6. git add + commit ONLY after steps 2-5 all green
  10. Common refactor-breaking error: CS0246 (type or namespace not found) usually means a new file was created but not referenced OR an extracted method left a dangling reference. Read the error location and verify both sites
  11. Project structure (relevant for where to place new partials): csharp/src/WKAppBot.CLI/Commands/ for CLI command handlers. csharp/src/WKAppBot.Win32/ for Win32 P/Invoke + UIA. csharp/src/WKAppBot.WebBot/ for CDP. csharp/src/WKAppBot.Vision/ for Tesseract + OCR. csharp/src/WKAppBot.Core/ for ScenarioRunner and ActionExecutor
  12. Partial-class pattern (for splits): new file must have namespace WKAppBot.CLI (or matching namespace) AND internal partial class Program (or matching container). No using-statement changes beyond what the extracted code actually uses

  16. DEPLOY ALL THREE (MANDATORY): when manually copying wkappbot-core.exe to bin/, always copy to wkappbot-core.exe AND wkappbot-core.new.exe AND wkappbot-core.exe.bak simultaneously. Eye FSW watches .new.exe and will hot-swap it back -- if .new.exe has an old/broken version, it reverts your fix. Single-file copy is insufficient. Pattern: Copy-Item good.exe bin/wkappbot-core.exe -Force; Copy-Item good.exe bin/wkappbot-core.new.exe -Force; Copy-Item good.exe bin/wkappbot-core.exe.bak -Force

  18. TWO-TREE ARCHITECTURE (MANDATORY, discovered 2026-05-18): This repo has TWO separate source trees -- (A) csharp/ = private internal source (v7.3.X) → deploys to bin/wkappbot-core.exe. (B) sdk/ = git submodule (***/wkappbot-sdk, v6.0.X) → deploys to sdk/bin/wkappbot-core.exe. These are DIFFERENT binaries at DIFFERENT paths. The user runs bin/wkappbot-core.exe. sdk/bin/ is the public SDK binary. NEVER confuse them.

The DeployToSdkBin target in the csproj auto-copies wkappbot-core.exe to bin/ (or stages .new.exe for hot-swap if Eye has the file locked).
