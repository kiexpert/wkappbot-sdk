admin Eye hot-swap: known gap, options for fix

Admin Eye currently has no FSW watcher. After normal Eye hot-swaps to a new wkappbot-core.exe, the admin Eye pipe (wkappbot_elevated) continues running the old binary. Options: version-check on each sudo invocation, admin Eye self-restart on stamp change, or document as acceptable (admin Eye is short-lived).

user/developer

Steps

  1. Current state: normal Eye FSW watches wkappbot-core.new.exe and renames it. Admin Eye (elevated) has no FSW, starts once per UAC elevation, runs old binary until user terminates session.
  2. Option 1 (recommended): SudoHandler checks binary stamp on each --sudo invocation. If stamp changed, terminates old admin Eye + re-spawns with UAC prompt. Cost: extra UAC prompt on first command after hot-swap.
  3. Option 2 (lightweight): Admin Eye watches its own exe path for mtime change (poll every 30s). On change, sets a flag; next command request triggers self-exit so launcher re-spawns.
  4. Workaround (current): restart admin Eye manually by killing it in Task Manager or using wkappbot eye (which terminates and re-spawns all Eye processes).
