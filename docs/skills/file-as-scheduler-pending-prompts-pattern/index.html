파일명이 곧 스케줄 -- pending_prompts 패턴

Zero-memory scheduler: filename encodes trigger time + repeat + countdown. No DB, no daemon, no in-memory state. Survives process restart/reinstall automatically. The file IS the schedule.

Steps

  1. INSIGHT: Store deferred prompts as files in {cwd}/.wkappbot/pending_prompts/. Filename encodes everything -- no JSON parse needed for scheduling decisions.
  2. FILENAME SCHEMA: prompt_{triggerUtc|NOW}_{guid8}[,rep=Nh|Nm|Ns][,cnt=N][,tod=HHMM-HHMM][,days=weekdays|weekends|mon-fri|1-5|mon,wed,fri].json
  3. TOD/DAYS GATE: tod=HHMM-HHMM (local time) + days=weekdays|weekends|mon-fri|mon,wed,fri skips DELIVERY but still reschedules (rep= rename). Prompt fires only inside window; outside window: silent skip + next trigger queued. Eye holds zero window state.
  4. TIME GATE: string.Compare(trigger, nowTag) <= 0 -- no JSON parse, no DateTime.Parse. NOW always passes. Sorted files give chronological delivery order. triggerUtc=yyyyMMddHHmmss (lexicographic sort = chronological).
  5. MANAGEMENT: wkappbot schedule pending list [--cwd <path>] -- shows all file-schedules with parsed params. wkappbot schedule pending delete <pattern|--all> [--cwd <path>] -- deletes by name substring or * glob. Only way to cancel infinite rep= (no cnt=) schedules.
  6. EXAMPLES: prompt_NOW_abc12345.json (session-miss, deliver asap), prompt_20260429090000_def,rep=24h.json (daily forever), prompt_20260429090000_ghi,rep=20m,tod=0900-1530,days=weekdays.json (weekday market-hours every 20min), prompt_20260429090000_xyz,rep=24h,cnt=5.json (daily 5x then done).
  7. TIME GATE: string.Compare(trigger, nowTag) <= 0 -- no JSON parse, no DateTime.Parse. NOW always passes. Sorted files give chronological delivery order.
  8. LIFECYCLE: rename on delivery → update trigger to next time, decrement cnt. cnt=0 → delete. rep without cnt → rename forever. File born → evolves → dies. Eye holds ZERO state in memory.
  9. ATOMIC CLAIM (race-free): File.Move(f, f+'.processing', overwrite:false). Only one thread wins. Loser skips. Error → rename back to .json for next drain retry.
  10. DRAIN TRIGGERS: (1) OnCommandArrived: any wkappbot cmd from that CWD fires immediately. (2) Eye startup AuditOnStartup. (3) Successful prompt delivery auto-drains siblings. (4) deliver_after: skip until time.
  11. SESSION-MISS: no target session → re-append with exponential backoff (30s→300s, infinite retries). No Slack escalation. No retry limit. File waits silently.
  12. DURABILITY: wkappbot uninstalled → files survive. Reinstall → AuditOnStartup finds files → delivers. The OS is the persistence layer.
  13. BEAUTY: cnt=5 recurring = 5 files created once, each self-destructs after delivery. OR one file with cnt=5 that renames itself 5 times then deletes. Same result, different philosophy.
