Launcher NativeAOT build needs vswhere.exe in PATH

RESOLVED in commit 65846b1: WKAppBot.Launcher.csproj now auto-prepends the VS Installer dir to the MSBuild process PATH before IlcCompile via a RoslynCodeTaskFactory inline task. Plain 'dotnet publish' from bash/cmd works without manual PATH setup. Skill retained as a reference for the symptom (MSB3073 vswhere not recognized) and how the csproj-embedded fix works.

Steps

  1. RESOLVED (commit 65846b1) — manual PATH export no longer needed. csproj now self-heals.
  2. SYMPTOM (if ever regressed): error MSB3073 'vswhere.exe' is not recognized ... command exited with code 123 during PublishAot native link.
  3. ROOT CAUSE: ILCompiler's native link target spawns vswhere.exe via <Exec> relying on PATH. vswhere lives at 'C:\Program Files (x86)\Microsoft Visual Studio\Installer' which is absent from default shell PATH outside Developer PowerShell.
  4. FIX IN csproj: UsingTask TaskFactory=RoslynCodeTaskFactory runs inline C# that calls Environment.SetEnvironmentVariable(PATH, installer-dir + ';' + currentPath). Triggered via Target BeforeTargets=CollectFrameworkReferences;PrepareForBuild;CoreCompile;IlcCompile and gated by PublishAot==true + Windows_NT.
  5. WHY MULTIPLE BeforeTargets: the first vswhere lookup happens in a pre-ILC target; a single BeforeTargets=IlcCompile fires too late. Prepending PATH across multiple early hooks covers all invocations; the task is idempotent (skips when already present).
  6. VERIFY: log shows '[AOT] prepended to PATH for vswhere: <dir>'. If you see the old MSB3073 error, check whether the inline task was removed or whether vswhere's location moved (2 candidates probed: Program Files (x86) and Program Files).
  7. CORE DOES NOT NEED THIS: WKAppBot.CLI.csproj is not PublishAot, so plain dotnet publish without vswhere works there.
  8. DEPLOY PATH: Launcher publishes wkappbot.exe (~3.6MB single-file AOT) to repo/bin via DeployLauncher target.
