Hangul IME Relay architecture and sync pattern

HangulImeRelay WH_KEYBOARD_LL hook: arch + bugs. KEY: daemon-only hook (Eye must NOT call Install), Global\WkImeRelay mutex singleton.

user/developer

Steps

  1. Architecture: WH_KEYBOARD_LL hook intercepts keystrokes for relay-only or broken IME targets. Do not query foreground IME state on every keypress; keep cross-process ImmGetContext reads out of KeyboardProc for healthy IME windows. Sync relay mode from initial install and foreground activation through ActivateForWindow and EVENT_SYSTEM_FOREGROUND. Do not force the system IME state from the relay. Healthy IME windows pass through; broken Win32 IME windows use the proxy/composer fallback. Files: HangulImeRelay.cs (_koreanMode flag + hook), .Composer.cs (syllable FSM), .ImeProxy.cs (proxy window), .Inject.cs (injection), ImeRelayDaemon.cs (lifecycle), AppBotEyeGlobalMode.cs (spawn). BUG 2026-05-08: _koreanMode hardcoded true on install -- fixed to call IsSystemImeKoreanMode() instead. BUG 2026-05-08: CreateImeProxy() forced ImmSetOpenStatus -- fixed to sync from system state. IsSystemImeKoreanMode() reads ImmGetContext(GetForegroundWindow()) then ImmGetOpenStatus()+ImmGetConversionStatus(). IME_CMODE_NATIVE=1 means Hangul active.
  2. BUG 2026-05-09: Path A (proxy) Backspace was flushing composition then passing BS to terminal. Fix: FeedKeyToProxy(VK_BACK) when composing. BUG 2026-05-09: Path B (FSM) jamo feed loop redundant erase+re-inject. Fix: track _prevPreviewChar, skip when !HasCommit && Preview==_prevPreviewChar.
  3. ARCH FIX 2026-05-09: Multi-daemon hook conflict -- toggle broken (commit 67531f0b). ROOT CAUSE: Eye called HangulImeRelay.Install() at startup AND ImeRelayDaemon.Spawn() spawned separate daemon that also installed WH_KEYBOARD_LL. Daemon singleton detection used log file scan but launcher never created log files -> every Spawn() call saw no daemon -> 3+ competing hooks. FIX 1: AppBotEyeGlobalMode.cs -- RelayWatchdog() no longer calls HangulImeRelay.Install(). Eye never installs hook. Daemon owns the hook exclusively. FIX 2: ImeRelayDaemon.cs -- Named Mutex Global\WkImeRelay as primary singleton gate. Spawn() checks MutexHeld() first. Run() creates mutex initiallyOwned=true; exits immediately if live owner holds it. Log-file scan kept only for version comparison during binary update. FUTURE: Store caller CWD as Window Property (SetProp) on Chrome window at launch -- current eye_ticks.jsonl PromptHwnd approach works but HWNDs go stale after session end.
  4. BUG 2026-05-09: HasRealImeContext returned true for Windows Terminal causing relay bypass. Fix commit 139cf6fb: check UnicodeWindowClasses before ImmGetContext. Windows Terminal / ConPTY are relay targets, not bypass targets; HasRealImeContext false-path is intentional so broken consoles can be relayed via Unicode/composer output when needed.
  5. Verified 2026-05-10: ev_ime_daemon_fix.sh (resolve ts=2026-05-10T14:38:07.7839150Z). 2026-05-12 input-time sync rule is superseded by the 2026-05-16 performance rule for healthy IME windows: do not use a focus hook to force _koreanMode, but also do not query foreground IME on every keypress. For broken targets, a foreground-arm hook may call ActivateForWindow(hwnd) so the relay is armed before the first character lands; this still must not force the system IME.
  6. PERFORMANCE 2026-05-16: Keep SyncRelayModeFromForeground and repeated ImmGetContext reads out of KeyboardProc. Healthy IME windows must pass through without per-key IME sync queries; sync relay mode on foreground activation through ActivateForWindow and the EVENT_SYSTEM_FOREGROUND hook, with only the one-shot broken-target correction after a relay-owned VK_HANGUL or VK_RMENU toggle.
