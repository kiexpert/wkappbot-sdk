Admin Eye Pipe Server -- Self-Respawn + Hot-Swap Deferral

Named pipe server (wkappbot_elevated) inside admin Eye. Handles admin commands, defers hot-swap while busy, and self-respawns on binary update using own elevated token -- no UAC.

Steps

  1. 1. NamedPipeServerStreamAcl.Create AuthUser=ReadWrite Admin=FullControl
  2. 2. WaitForConnectionAsync -> Task.Run HandleClient -> Interlocked _activeClients counter
  3. 3. HandleClient: ReadAsync EyeProxyRequest -> ExecuteCommand -> WriteAsync response
  4. 4. IsBusy guard: hot-swap deferred while _activeClients > 0
  5. 5. __eye_tick__ special: returns cached Eye loop state without subprocess
  6. 6. StopAcceptingAndWaitForDrain: 30s drain cap
  7. ## Self-respawn on binary update (AppBotEyeCommands.cs)
  8. Dual FSW 감시: .new.exe 등장(조기 drain) + .exe 직교체(fast-path) 동시
  9. .new.exe path: IsBusy drain -> .new.exe 소멸 대기(swap 확인) -> spawn successor
  10. .exe path: drain 중이면 자연 완료, 아니면 즉시 spawn
  11. Process.Start(UseShellExecute=false, 'eye --elevated') -- 부모 elevated 토큰 상속, UAC 없음
  12. drainTriggered flag: 두 FSW 동시 발화 시 중복 spawn 방지
  13. startup 시 .new.exe 이미 있으면 즉시 drain 시작

SUDO STABILITY FIX (2026-05-01, commits 4af2b2bc + 4ebb597c): Root cause of 15-commit instability loop — SudoHandler.SpawnAndAwaitAdmin and LaunchElevatedEye ran as TWO SEPARATE spawn paths with no shared mutex, so concurrent --sudo callers each showed their own UAC dialog, each spawned admin Eye, and both raced to bind wkappbot_elevated_<hash> pipe. Every prior fix patched symptoms (cooldown timers, kill-on-cancel, infinite-poll) not the cause. Fix 1: SudoHandler collapsed into thin wrapper delegating to LaunchElevatedEye only — single mutex-protected path, 220 lines of duplicate spawn logic deleted. Fix 2: Mutex replaced with Named Semaphore (System.Threading.Semaphore) — Mutex is OS-thread-affine, ReleaseMutex from different async thread-pool thread throws ApplicationException and mutex stays held forever. Semaphore has no thread affinity. Fix 3: [ThreadStatic] _launchInProgress re-entrancy guard — same-thread re-entry now returns immediately instead of running duplicate spawn. Fix 4: proc.Kill(entireProcessTree:true) added on pipe-timeout path to prevent orphan admin Eye when UAC approved but pipe never came up.
