AppBot Log Explorer

Find and interpret WKAppBot logs across command-specific files, runtime history, errors.jsonl, skill invocation logs, and caller process chains. Use when tracing ask, suggest, skill, chat, codex, eye, or file behavior, or when you need the right log file after a failure.

Steps

  1. Start from .wkappbot/hq/logs/ and .wkappbot/hq/runtime/; use command_history.jsonl as the index when the target log file name is unclear.
  2. Trace the caller chain first when a process storm is active: inspect Win32_Process ParentProcessId, command lines, and the nearest command_history.jsonl entry to identify the launcher that spawned eye, speak, codex, or chat.
  3. Map the command to its log family: old ask ..., old eye ..., old skill ..., old file ..., old agent ..., old a11y ..., old prompt ..., and the matching wkappbot-core.exe.out-*.log file.
  4. For failures, check errors.jsonl first, then the command-specific .log, then command_history.jsonl, then skill_invocations.jsonl or skill_seen.jsonl if the command touched skills.
  5. For UI or routing stalls, search for FindAllPrompts, focus_stolen, via_eye, resume --last, WKAPPBOT_CHAT_SESSION, timeout, and blocked.
  6. Use wkappbot logcat for quick filtering when the log file is known, or open the exact command family folder when the command name is known.
  7. Correlate the timestamp in command_history.jsonl with the nearest wkappbot-core.exe.out-*.log under old <command>/ when the failure happened in a multi-stage run.
  8. Use scripts/find-wkappbot-caller-chain.ps1 for a fast live caller-chain snapshot before digging through logs.
  9. For blocked launcher or sudo storms, inspect the live caller chain before digging into log families, and search for WKAPPBOT_SUDO_ACTIVE, --sudo, --timeout, pipeTimeoutMs, control-return, blocking, and semaphore/gate traces.
  10. [CDP:DIALOG:BLOCKED] log pattern: Chrome JS alert/confirm/beforeunload blocked a11y/CDP commands. Auto-dismissed. Search in ask/web command logs. Also fires wkappbot speak audible alert.
  11. [CDP:NODE-ERROR] log pattern: node access failure (No node with given id / Cannot find context / detached). Followed by page inspection dump: URL, title, readyState, dialog nodes, top-8 interactive targets with selectors. Use the sel/id fields to retarget.
  12. [REAPER] log pattern: idle tab recycled (ping+navigate) or killed. [REAPER] Recycled = reuse success. [REAPER] Closed = renderer dead or dialog blocking, new tab will be created on next ask.
  13. [TAB-CAP] log pattern: oldest tab killed to enforce 9-tab limit. Fired on every ask entry (EnforceTabCapAsync).
