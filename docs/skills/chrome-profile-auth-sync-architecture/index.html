chrome-profile-auth-sync-architecture

WKAppBot Chrome profile auth sync: master->project copy on launch, project->master SQLite merge on exit. Use when sessions expire frequently or cookies not persisting across projects.

user/developer

Steps

  1. ARCHITECTURE: Master profile at {DataDir}/chrome-profiles/master/, per-project at {DataDir}/chrome-profiles/{hash8(cwd)}/
  2. ON LAUNCH (CopyFromMaster): copies Default/Login Data + Default/Cookies + root Local State (DPAPI key) from master to project. Skip-if-fresh: skips copy if project copy is newer than master. DPAPI Local State MUST travel with Cookies or decryption fails silently
  3. ON EXIT (MergeBackToMaster): SQLite merge of persistent+unexpired cookies (is_persistent=1, expires_utc!=0, expires_utc>now) and new Login Data rows from project back to master. Master Chrome must NOT be running during merge (SQLite corruption risk)
  4. SESSION COOKIES NOT SYNCED: expires_utc==0 (session-only cookies) are excluded by design. Sites that use only session cookies will always re-auth on Chrome restart -- this is expected
  5. TROUBLESHOOT auth expiring: 1) Check [CHROME:BOOTSTRAP:ERROR] in Eye log (DPAPI key mismatch) 2) Check MergeBackToMaster ran on last Chrome exit 3) Check master profile path exists: {DataDir}/chrome-profiles/master/Default/Cookies 4) Sites using session-only cookies cannot be persisted via this mechanism
  6. KEY FILES: ChromeProfileSync.cs (launch copy), ChromeProfileSync.Sql.cs (merge logic), ChromeProfileSync.Watch.cs (FSW live merge driver), ChromeProfileSync.Merge.cs (Local State DPAPI merge)
  7. IMPORT FROM PERSONAL CHROME: Copy cookies from user's regular Chrome into master profile. Steps: 1) Close personal Chrome first (SQLite lock). 2) Source: %LOCALAPPDATA%\Google\Chrome\User Data\Default\Cookies and Login Data. 3) Run MergeBackToMaster(personalChromeDefault, masterDefault) -- same SQLite merge logic, only persistent+unexpired cookies. 4) Copy Local State os_crypt key from personal Chrome to master if master has no DPAPI key yet. NOTE: personal Chrome uses same Windows user DPAPI key so encrypted_value decrypts correctly.
  8. IMPORT FROM PERSONAL CHROME: Copy cookies from user's regular Chrome into master profile. Steps: 1) Close personal Chrome first (SQLite lock). 2) Source: %LOCALAPPDATA%\Google\Chrome\User Data\Default\Cookies and Login Data. 3) Run MergeBackToMaster(personalChromeDefault, masterDefault) -- same SQLite merge logic, only persistent+unexpired cookies. 4) Copy Local State os_crypt key from personal Chrome to master if master has no DPAPI key yet. NOTE: personal Chrome uses same Windows user DPAPI key so encrypted_value decrypts correctly.
  9. CURRENT BOOTSTRAP FLOW (personal Chrome import): Called once at first launch (guarded by {masterDir}/.bootstrapped sentinel). Code: ChromeLauncher.BootstrapMasterFromSystemChrome() -> CopyIfNewer(systemChrome/Cookies, master/Cookies). BUG: CopyIfNewer does FULL FILE COPY when src.mtime > dst.mtime -- replaces entire master SQLite with personal Chrome file, losing any valid wkappbot session cookies. Trigger: delete .bootstrapped sentinel to re-run.
