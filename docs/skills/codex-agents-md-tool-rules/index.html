Codex AGENTS.md Tool Rules

AGENTS.md rules that guide Codex to use Claude-named cmd wrappers instead of native write_file/read_file tools. Required for harness integration to work correctly.

user/developer

Steps

  1. PURPOSE: AGENTS.md is loaded by Codex at session start. Use it to mandate wrapper usage instead of native Codex file tools.
  2. FORBIDDEN LIST: write_file, read_file -- both blocked by wkharness hook (exit 2 with redirect message).
  3. REQUIRED PATTERN: all file writes via shell echo json pipe Write.cmd. All file edits via shell echo json pipe Edit.cmd. All reads via shell echo json pipe Read.cmd.
  4. JSON FORMAT for shell calls: {tool_name:'Write',tool_input:{file_path:'abs/path',content:'...'}} piped to cmd via shell. tool_name must match Claude built-in name exactly for guards to fire.
  5. AGENTS.MD SECTION TO ADD: ## Tool Usage (MANDATORY) - FORBIDDEN: write_file, read_file (hook blocks these with exit 2). REQUIRED: shell to pipe JSON to Write.cmd / Edit.cmd / Read.cmd. Example: shell 'printf ...
  6. Write.cmd'
  7. PATH REQUIREMENT: WKAppBot/bin/ must be early in PATH so Edit.cmd, Write.cmd, Read.cmd resolve before system commands. Add to Codex env or system PATH.
  8. AGENT-CMD-MANDATORY (2026-05-24): All agent/subagent delegation MUST go through Agent.cmd (not direct wkclaude calls). Agent.cmd is in WKAppBot/bin/. Usage: Agent.cmd 'prompt' [--model haiku|sonnet|opus] or echo json | Agent.cmd. Guards enforced per call: brief-guard (3+ skill reads), spec-gate (opus needs SPEC block), claude-md-sync. wkclaude-direct-guard in wkharness-guards.ps1 blocks direct wkclaude invocations from shell tools. AGENTS.md section 17 documents all wrapper mappings.
  9. AGENT.CMD STDIN-HEREDOC FOR MULTILINE PROMPTS (2026-05-27): When Agent.cmd receives a multiline spec block or task prompt, use bash heredoc with quoted delimiter to preserve characters verbatim. Pattern: Agent.cmd --model opus << 'EOF' (followed by prompt lines, then EOF on its own line). Single-line ASCII: Agent.cmd 'text' --model opus OK. Heredoc is REQUIRED for SPEC blocks (multiline) or prompts containing shell metacharacters (&, |, <, >, ^) to avoid cmd.exe re-parsing corruption.
